What bbh could take from simmis

Goal: find what bbh could borrow from replikativ/simmis, rank those ideas by value against effort, and say what to skip. This doc proposes changes and makes none.

Short answer

simmis is a large alpha workspace: chat rooms, a wiki, a ledger and agents, all on the replikativ stack. It has about 530 source files under src/is and 550 under test/is (measured: git ls-files). Most of its big ideas already exist in bbh in another form. Its forks plus proposals are bbh's jj workspace, review ask and landing. Its failure is a value, never a fallback rule is already a bbh rule. Its SCI sandbox with a documented vocabulary is bbh's Router sandbox and verb table. Four things are worth taking:

  1. Recall with citations over past threads (high value, low effort).
  2. Known-hole tests for the security gaps bbh already documents (medium value, low effort).
  3. Spend allowances per Worker, where a child's budget is taken from its parent's (high value, medium effort).
  4. A benchmark of the Router on frozen past requests (medium value, low to medium effort).

Two more fit later: paused scheduled Workers and egress capabilities. Each is blocked on the allowance or on process isolation.

In practice there is almost nothing to lift. simmis is JVM Clojure built on Datahike, spindel and dvergr, and its libraries carry their own licences, which its README notes. Take the ideas, not the code.

Value against effort

Placements are my judgement (inferred), not measurements. Green: do soon. Amber: needs a design pass. Red: blocked on process isolation.

Ranked ideas

1. Recall with exact citations

simmis: memory/search and memory/read return bounded results with receipts. Its digest design (doc/conversation-digests-and-knowledge.md) rests on one rule: a digest is not an admission filter. A summary only points the way. Any claim must cite exact original messages, and processing records which originals it covered.

bbh today: the design says archived threads, their summaries, events and conversation links are "kept indefinitely and searchable", and adds "no memory subsystem until that is a problem" (docs/super-agent.md §14). But no search verb exists. The Router's read verbs are super-threads, super-thread, super-events and super-projects (measured: src/bbh/super/verbs.clj). So "what did we decide about kanata chords last month?" means paging through events by hand.

Sketch: add an SQLite FTS5 table that the controller fills from events as it commits them: thread titles, notes, ask text and details, reply notes, and Worker briefs and final reports. Then add a read verb, (super-search "kanata chord" {:limit 10}). Each hit returns {:thread :seq :kind :snippet} and the messages.jsonl path of the conversation behind it. The Router and Workers then read the originals for the details. Add no model-written summaries. Thread notes are already summaries, and the citation rule keeps them hints. Effort: one migration, a fold hook and a verb, about 100 lines plus a test (inferred).

2. Known-hole tests

simmis: its authority tests (CLAUDE.md, Testing) run real attacks. An attack that still succeeds is a known-hole test. It passes while the hole is open and fails once it is closed, which forces whoever closes it to flip it into a refusal test.

bbh today: docs/super-agent.md §10 names two holes in prose. A Worker can read the owner token at ~/.local/share/bbh/super/token, and it can forge a tailscale-user-login header to the loopback web server. No test pins either (measured: no match for known.hole in test/).

Sketch: add one test file. It starts a scratch controller, opens a Worker token, and asserts that (a) the owner token file is readable from the Worker's uid and (b) a forged header is accepted. Each test carries the comment "known hole, see super-agent.md §10". When bubblewrap or a separate uid closes a hole, its test fails and becomes a refusal test. Effort: an hour or two with the existing scratch stack (inferred).

3. Spend allowances that conserve budget

simmis: every Run draws on a finite allowance held in its kontor ledger. Delegation is attenuation, not inheritance: a child grant's budget is debited from its parent and does not copy the parent's ceiling (doc/tool-authorization.md). Background work needs "a configured model, a finite allowance and explicit activation". Subscription use still counts against the allowance even when its dollar cost is zero.

bbh today: each conversation records tokens and cost in runs.jsonl, and /usage shows subscription limits. The controller has no budget concept (measured: no budget, allowance or cost match in src/bbh/super/). policy.edn allows ten Workers, and the design itself expects parallel Workers to use up subscription limits faster (§12).

Sketch: add an optional :allowance {:tokens 5e6} or {:usd 3} on super-start!, with a default in policy.edn. The session already writes usage, so it sends a :usage! command after each turn, and the fold sums usage per Worker and thread. When usage crosses 80 %, the controller files an ask: "T12 used 4M of 5M tokens: extend, stop, or let it finish". At 100 % the Worker is held after its current turn. If Workers ever start child Workers, the child's allowance is taken from the parent's. Effort: a few events, a fold rule, one ask path and TLA+ model updates (the verify skill applies), about a day (inferred).

4. A frozen benchmark for the Router

simmis: a workflow is benchmarked on retained cases with evaluator-held answers and frozen inputs, and the candidate's cost counts toward the result (doc/coordinator-work.md, doc/wiki-maintenance-workflow.md). A completed run never proves its answer is right.

bbh today: rollout phase 4 says "routing accuracy on real requests is not yet measured", and the Router model choice waits on that number (§13, §14). bbh already has fork replay (eval/README.md), which resumes a recorded session under another prompt without running tools.

Sketch: take 30 to 50 past :message events the Router handled. Label each with the correct action (thread and verb) in an EDN file kept outside the Router's sight. Fork-replay the Router on each under candidate prompts and models, and score the first verb it called against the label. Report accuracy and cost per arm. This is the measurement §14 asks for, built on code that exists. Effort: low to medium. Labelling is most of it (inferred).

5. Scheduled Workers, installed paused

simmis: a schedule is installed inactive. Activation, model choice and a finite allowance are separate explicit steps. Results land as proposals and are never merged automatically.

bbh today: "work the agent starts on its own" is listed under Later (§11), with speculative threads that stay in Quiet until wf reaches done with an independent review.

Sketch: a schedules.edn entry {:id :doom-doctor :cron "0 7 * * 1" :brief … :workflow :investigation :allowance … :enabled false}. The controller's health pass appends a :schedule-due event, which starts a Worker on a speculative thread. Enabling a schedule is an ask. Needs idea 3 first, so a schedule cannot spend without a cap. Effort: medium (inferred).

6. Egress as a capability granted in advance

simmis: "review cannot cover irreversible actions: by the time you are reviewing, the mail has been sent". So email, HTTP, money and pushes are authorized in advance with a budget, and writes are reviewed after the fact (doc/agents.md).

bbh today: code goes through review before landing, and make switch is always an action ask. The design admits that a Worker with a shell under your uid can do anything, and that a controller check cannot close that (§10).

Sketch: once Workers run in bubblewrap or a Guix container, give each Worker a :may #{:push :http :mail} set on start. The container gets network or a credential only for the listed kinds. Until isolation exists, this would be honour-system only, so skip it for now and keep the principle in the design doc. Effort: high, mostly the isolation (inferred).

7. An as-of view of controller state

simmis: Datahike stores history, so any store can be read as-of a point in time, and the UI shows how a page reached its current state.

bbh today: the state is already a fold over an append-only SQLite log with snapshots (src/bbh/super/store.clj replay). So an as-of view is a fold that stops at sequence number N.

Sketch: add bbh super state --at SEQ for debugging ("why was T40 in Stopped yesterday?"). Small and low value, but nearly free (inferred).

Skip, and why

simmis ideaWhy skip
Datahike, konserve, yggdrasil and kabel as the storebbh has one writer and one reader on SQLite, with idempotent commands and a fold that TLA+ models. Datahike would add a JVM or a pod and replication bbh does not need. Time travel comes nearly free from the log (idea 7).
Forks and proposalsAlready there: a jj workspace per Worker, a review ask on an immutable revision plus evidence hash, stale approvals rejected, and landing on your line.
SCI sandbox with documented vocabularyAlready there: the Router runs sandboxed with BBH_ROLE=router, and every verb carries a :doc. simmis calls its own sandbox a soft boundary, which is no better than bbh's.
Humans and agents as one kind of party; ReBAC grants; JWT audiencesMulti-user machinery. bbh has one person, and its tokens already separate you, the Router and each Worker.
Telegram mirror of roomsThe phone page over tailscale serve covers this, with the owner-login check and no third party.
Model family resolution (latest version in a family, never fall back across families)Claude Code resolves models, and policy.edn pins a short list. The useful part, never falling back silently, is already a bbh rule.
Compaction coverage markersbbh never compacts. It rolls over to a new conversation that points at the old messages.jsonl.
Agent-to-agent hop budget, reset by human input (roadmap)bbh Workers do not message each other. Revisit if they ever do.
Ledger, wiki, office documents, screen captureProduct features of a team workspace, outside a coding-agent harness.
Transcripts that wake no agentA nice rule ("an hour of call is nobody's turn"), but bbh voice is dictation aimed at the Router. It becomes relevant only if bbh starts recording meetings.

One caution from reading it

simmis's docs are long and dense with invariants: doc/authority.md is 1,335 lines and doc/architecture.md is 1,264 (measured). The code they describe is alpha, and the README lists real gaps, such as blob reads that are authenticated but not authorized. The thing worth copying is the habit of naming each invariant and testing it, as in idea 2. The volume of prose is not.
