Reloading your Chrome extensions with one command

Pick: a small helper extension plus a local hub, behind one command, ext-reload NAME. It builds the extension, reloads it from disk in your running Chrome (or turns it on if it was off), then reloads the open tabs its content scripts match. It does this without clicks and without opening a DevTools port. Guix declares it in modules/engstrand/features/chrome-extensions.scm: the list of extensions, the Flatpak read grants and the hub service.

What Chrome is here

  • Flathub Flatpak com.google.Chrome 157.0.8103.38, branded stable. Guix only sets it as the default browser through MIME settings.
  • The profile is Chrome's default one, ~/.var/app/com.google.Chrome/config/google-chrome.
  • Your Flatpak overrides already give Chrome read-only access to ~/projects/vimium-cljs/ext and ~/projects/cookie-autoaccept. Your current loads still go through /run/flatpak/doc/… portal paths.

How the pick works

  1. ext-reload vimium-cljs looks up the name in ~/.config/ext-reload/extensions.edn, which Guix writes, and runs that project's own build (./build.sh or npm run build).
  2. It reads the manifest's name and content_scripts.matches, then posts them to the hub on 127.0.0.1:7357. The hub refuses requests that lack an X-Ext-Reload header, which keeps web pages out.
  3. The helper extension (fixed id hhphiidacaejhbolcnboolfapncammkf) holds a WebSocket to the hub. It finds the unpacked extension by name, disables and re-enables it so Chrome reads it from disk again, and reloads the matching tabs. Pass --tabs active or --tabs none to narrow that. It replies with the version and the tab count, or tells you that Chrome would not load the build.
  4. The helper lives in ~/.var/app/com.google.Chrome/data/ext-reload/reloader, a folder the sandbox can always read, so it needs no override and no restart. The hub copies it there from the repo when it starts. If the copy changed, the hub tells the running helper to reload itself.

What is still manual, once

  • Load the helper with Load unpacked once. Chrome offers no way to add an extension from outside except policy (root plus a packed CRX). Chrome remembers it after that.
  • Each new extension you develop needs Load unpacked once, using its real path under ~/projects. After that, ext-reload handles it, including turning it back on if it was off. When an extension is missing, the command prints the exact path to load.
  • Guix gives Chrome read access to each project directory rather than its ext/. cookie-autoaccept's build deletes and recreates ext/, and a Flatpak grant on that folder would keep pointing at the deleted one. A new grant takes effect after Chrome restarts.

Commands

ext-reload vimium-cljs            # build, reload, reload matching tabs
ext-reload cookie-autoaccept --no-build --tabs active
ext-reload list                   # registry and the unpacked extensions Chrome has
herd status ext-reload            # the hub; log in ~/.local/state/ext-reload.log
make ext-reload-test              # end to end in a throwaway headless Chrome
