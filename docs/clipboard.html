Copy and paste: why Cmd+C sometimes did nothing

In short

Copies from Emacs or Neovim in the terminal failed without a word, so the clipboard kept its old text and the next paste, in Chrome or anywhere else, gave the old text. Chrome was never at fault. Two terminal settings caused it, and both are fixed. The rule now: Cmd is the clipboard key everywhere, and Ctrl keeps each app's own meaning.

The old path

kanata sends one chord for each clipboard key, whatever window has focus: Cmd+C is Ctrl+Insert, Cmd+V is Shift+Insert and Cmd+X is Shift+Delete. These chords mean copy, paste and cut in every GTK, Chrome, Emacs and JetBrains window, and they never collide with a terminal's Ctrl+C. The per-app layers that hyprkan switches don't touch them, so a late layer switch can't break copy. Hyprland binds none of these chords, and vimium-cljs passes them to the page.

The cause

  • Ghostty binds Ctrl+Insert to its own copy by default. Herdr and the editors handle the mouse, so Ghostty usually has no selection. It then copied nothing and still swallowed the key, so Emacs never saw C-<insert>.
  • Neovim copied and cut on Ctrl+C and Ctrl+X, but Cmd+C sends Ctrl+Insert, so Cmd+C did nothing there in any terminal. Caps+C worked, which is why both chords seemed to work only some of the time.

What was ruled out, on the hidden test display: Flatpak Chrome copies, pastes and cuts on kanata's chords every time, including 20 of 20 pastes straight after a focus switch. kanata's layer switching, Hyprland binds, vimium-cljs, the cliphist watcher and Emacs's Wayland clipboard functions all checked out.

The new design

KeySendsMeaning
Cmd+C / V / XCtrl+Insert, Shift+Insert, Shift+DeleteCopy, paste, cut in every app
Ctrl (Caps) + C / V / XUnchangedThe app's own: SIGINT in terminals, block visual in Vim, copy in Chrome
Cmd+Caps+VSuper+Ctrl+VClipboard history
  • Ghostty (Herdr's window and the ghostty-rex window) unbinds its default and rebinds Ctrl+Insert with performable:. Cmd+C now copies Ghostty's own selection (Shift+drag) when there is one, and otherwise passes the key to the program.
  • Neovim copies and cuts on <C-Insert> and <S-Del>. Its Ctrl+C, Ctrl+X and Ctrl+V clipboard maps are gone, so Ctrl keeps Vim's meaning. Cmd+V reaches it as Ghostty's paste.
  • Emacs needed no change: C-<insert>, S-<insert> and S-<delete> are its built-in copy, paste and cut.

Check

make verify ONLY=clipboard-e2e opens Flatpak Chrome, terminal Emacs (in both Ghostty configs), Neovim and a shell on the hidden test display. Before each step it moves focus to another window, then sends kanata's chords. It checks a copy into and out of each app, a cut in Chrome, a copy of Ghostty's own selection, and that Ctrl+C still interrupts a program in the terminal. Before the fix 3 of its checks failed. Now all 14 pass.

To reload

  • Ghostty: the configs are stowed, so press Ctrl+Shift+Alt+R in Herdr's window and in the Rex window, or open a new window.
  • Neovim: restart open sessions.
  • Nothing for kanata, Hyprland, Chrome or Emacs.
