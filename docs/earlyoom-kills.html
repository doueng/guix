earlyoom kills readable without root

Outcome

earlyoom now writes one line per kill to /var/log/earlyoom-kills.log, mode 0644, so you and agents can read it without sudo. bbh super list shows the last kill on its machine line. Built and committed, not applied yet: applying it needs sudo.

Apply and check

make switch

Then:

ls -l /var/log/earlyoom-kills.log
cat /var/log/earlyoom-kills.log
sudo herd status earlyoom

Expect -rw-r--r-- root root. The file starts empty and gets a line only when earlyoom kills something. A line looks like this:

2026-11-12T21:55:24+0000 pid=43 uid=1000 name=bb

make switch restarts earlyoom only if shepherd upgrades it in place. If sudo herd status earlyoom still shows the old command line without -N, run sudo herd restart earlyoom or reboot.

Why this option

  • Making /var/log/earlyoom.log group-readable doesn't hold. Shepherd creates that file 0640 root:root, and it does so again after every restart and log rotation. An activation chmod would be undone the first time either happens.
  • It would also leak. earlyoom's kill line includes the victim's full command line, and a command line can hold a token. The new hook writes only the time, pid, uid and the 15-character process name. It never reads EARLYOOM_CMDLINE.
  • It's small and needs no upkeep. The hook is a three-line bash-minimal script that runs once per kill, and one line per kill needs no rotation. An activation snippet creates the file at 0644 so readers find it before the first kill.

What was checked

  • make lint and make build pass (offloaded to the builder). The built earlyoom service passes -N /gnu/store/…-earlyoom-kill-hook.
  • I ran the built hook against a temporary file. A name containing a space and a newline came out as ld-linux_aarch6_, and a secret in EARLYOOM_CMDLINE didn't appear in the output.
  • bbh super list's line read the last line from that file: …; last earlyoom kill: 2026-11-12T21:55:24+0000 pid=43 uid=1000 name=bb. bbh.sessions-test passes (12 tests).

Limits

The new file records kills from now on only. To check the 2026-11-12 exits 137 and 143 you still need sudo grep -i sending /var/log/earlyoom.log. The hook isn't told whether the signal was SIGTERM or SIGKILL. That detail stays in the root-only log.
