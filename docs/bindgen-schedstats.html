bindgen, CONFIG_SCHEDSTATS and Rust struct layouts in your Asahi kernel

T215, W278, 2026-11-22. Kernel: linux-asahi 7.2.15-1 from /home/engstrand/guix/modules/engstrand/asahi/kernel.scm

Verdict. Your running kernel does not misread task_struct.mm. It was built with bindgen 0.71.1, which pads task_struct explicitly, so every field offset matches C measured. The bug Aurora hit needs bindgen 0.73.2. Your kernel still has a smaller version of the same bug class: 13 Rust types disagree with C, and the kernel's --no-layout-tests hid them. The fix makes those types opaque and turns the layout assertions back on, so any future mismatch fails the build.

What Aurora reported

Aurora's Documentation/rust/bindgen-layout-checks.rst on integration/aurora says the following. With CONFIG_SCHEDSTATS=n, struct sched_statistics is empty but ____cacheline_aligned. Stock bindgen drops the alignment of an empty struct, so task_struct fields after stats, including mm, moved 40 bytes in Rust on their defconfig plus Asahi config. Rust passed a wrong pointer as the current mm, and the Asahi GPU driver's RSS charge faulted in percpu_counter_add_batch.

Their fix has three parts. They keep bindgen's layout assertions in every build, they add --opaque-type sched_statistics to rust/bindgen_parameters, and they ship a patched bindgen 0.73.2 in tools/aurora-bindgen.

  • https://github.com/aurora-silicon/linux/pull/607 keeps layout checks in every build. It describes the percpu_counter_add_batch fault.
  • https://github.com/aurora-silicon/linux/pull/992 makes sched_statistics opaque. With bindgen 0.73.2, Rust had stats at 792 and C had it at 832.
  • https://github.com/aurora-silicon/linux/pull/726 adds a warning when the selected bindgen has the alignment bug.
  • https://github.com/aurora-silicon/linux/blob/integration/aurora/Documentation/rust/bindgen-layout-checks.rst
  • https://github.com/aurora-silicon/linux/tree/integration/aurora/tools/aurora-bindgen has the bindgen patches 0001-empty-alignment.patch and 0002-anonymous-tag-members.patch.

Others who hit it

  • Rust for Linux #1269 (Jules Mercier, 2026-11-13, open). On a OnePlus 6T, arm64, bindgen 0.73.2 put task_struct fields 48 bytes early. As a result, Rust Binder called mmgrab on a bogus mm, every binder mmap failed with EINVAL, and Waydroid would not start. Miguel Ojeda wants bindgen fixed before the next minimum-version bump, and the layout tests enabled. https://github.com/Rust-for-Linux/linux/issues/1269
  • Kernel patch, “rust: bindgen: Preserve sched_statistics alignment” (Peder Bergan, 2026-11-19, v1 under review). It adds --opaque-type sched_statistics, and Jules Mercier sent a Tested-by. With 0.73.2, mm was at 1168 in Rust and 1208 in C. Ojeda says the misplacement appears only with bindgen 0.73.2, because earlier versions add explicit padding. He accepts the patch as a temporary workaround, and a v2 is expected. https://lore.kernel.org/rust-for-linux/20261119-fix-schedstats-bindgen-layout-v1-1-0599dd230ffd@gmail.com/
  • bindgen #3549, “Empty struct with __attribute__((aligned(N))) is emitted without #[repr(align(N))]” (open), has a standalone reproducer. https://github.com/rust-lang/rust-bindgen/issues/3549 The duplicate #3552 is closed. https://github.com/rust-lang/rust-bindgen/issues/3552
  • bindgen PR #3555, “Add repr(align) to over-aligned empty structs” (open, not merged). It is the root-cause fix, and Peder Bergan checked that it puts mm back at 1208. https://github.com/rust-lang/rust-bindgen/pull/3555
  • gaokun-android PR #138 turns SCHEDSTATS on for Linux 7.4 because Rust Binder reads the wrong mm otherwise. https://github.com/vahiru/gaokun-android/pull/138
  • Why the kernel has no check: Rust for Linux PR #820 (2022) stopped generating layout tests, since they were never run. https://github.com/Rust-for-Linux/linux/pull/820
  • Searched with no hits: the AsahiLinux GitHub org (issues and PRs for sched_statistics, percpu_counter_add_batch, bindgen alignment). I did not search the Asahi Matrix logs or the Fedora Asahi trackers.

bindgen has no released fix. 0.73.2 is the latest release, and PR #3555 is open. No minimum bindgen version avoids the bug.

bindgen 0.71.1 emits pub __bindgen_padding_1: [u64; 5usize] before stats. Those 40 bytes are the gap the lost alignment would otherwise leave, so mm stays correct measured. With the assertions on, the unpatched source still fails with 13 E0080 errors across bindings and uapi:

  • sched_statistics alignment is 1 in Rust and 64 in C. This is the bug in bindgen #3549. It is harmless with 0.71.1, but it would move mm as soon as Guix ships bindgen 0.73.2.
  • ns_common is 128 bytes in Rust and 256 in C. bindgen drops the anonymous struct ns_tree; member, which the kernel's -fms-extensions allows. That makes pid_namespace, user_namespace and cgroup_namespace too small, and fields after their ns member sit 128 bytes early in Rust. No Rust code in this tree reads those fields inferred from grep. Aurora's patch 0002 fixes this in bindgen.
  • efi_signature_data_t alignment is 1 in Rust and 4 in C, because bindgen drops the __aligned on the efi_guid_t typedef.

The fix

/home/engstrand/guix/modules/engstrand/asahi/patches/linux-asahi-bindgen-layout.patch is applied to the kernel source:

  • rust/bindgen_parameters gains --opaque-type for sched_statistics (the same line as the upstream patch), efi_guid_t, ns_common and its inner anonymous types. An opaque type takes its size and alignment from clang. Rust gets #[repr(align(64))] sched_statistics, and no Rust code reads these fields.
  • rust/Makefile drops --no-layout-tests. bindgen then emits const assertions for the size, alignment and every field offset of each type it generates, and rustc fails the kernel build if any of them differs from C. This is the build-time check. It covers task_struct, sched_entity and every other emitted type, for any future bindgen or config change.

After the patch, the repro finds 0 assertion failures, and the C, clang and Rust offsets above still agree measured.

Rejected options. Turning on CONFIG_SCHEDSTATS only hides this one type, as Aurora's doc also says. The cost is small: it adds a few hundred bytes to every task, and the accounting code sits behind a static key that is off by default. But it would not fix ns_common or efi_guid_t, and it would leave the next mismatch unchecked. Patching Guix's bindgen with PR #3555 would be the real root-cause fix, but the PR is unmerged and unreviewed, 0.71.1 already gets task_struct right, and the assertions would catch a regression. Revisit it when bindgen releases the fix.
