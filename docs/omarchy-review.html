Omarchy review and iPhone file sharing

Goal. Find what in Omarchy (cached at /home/engstrand/.cache/checkouts/github.com/omacom/omarchy, commit 3f974d0, 2026-11-13) is worth porting to your Guix, Hyprland and dusk setup, and pick a way to move files between the laptop and your iPhone. No config was changed.

Short answer. For files, use Taildrop with a small receive service, plus a tailscale serve share folder for laptop to phone downloads. Omarchy ships exactly this receive loop (omarchy-tailscale-receive), so the design is proven. Of the other ideas, clipboard history, the capture extras and idle lock give the most for the least effort.

Context: Omarchy no longer uses Waybar, Mako or Walker. A Quickshell shell (shell/shell.qml) now draws the bar, menus, notifications, OSD, clipboard and lock screen, and its Hyprland config is Lua, like yours. Omarchy does not support Apple Silicon (manual/44-mac-support.md), so every Asahi note below is mine. Notes marked inferred are not tested.

File sharing with the iPhone

Taildrop Recommended

For: Works over the tailnet anywhere, built into the Tailscale iOS app share sheet (pick Tailscale, pick the laptop). Phone receives into Files, Tailscale folder. You already run tailscale everywhere.

Against: Needs the receive loop on Linux, since tailscaled only queues files until something runs tailscale file get. Files only, no clipboard.

tailscale serve of a share folder Recommended as the second one

For: Laptop to phone without any app: tailscale serve a directory such as ~/Share at a path, open it in Safari on the phone, tap to download. Your bbh web already uses tailscale serve, so the pattern is known. Could live on the builder for always-on.

Against: Read-only download, no upload from the phone. Make sure it is tailnet-only (serve, not funnel).

LocalSend Good fallback

For: Free iOS app, AirDrop-like, also does text. Omarchy ships it and has a share menu for clipboard, file or folder.

Against: Same LAN only, so it fails on cafe Wi-Fi with client isolation. Not in Guix; Flathub has an aarch64 build (inferred), firewall ports 53317 TCP and UDP.

Second-brain or reader share folder on the builder Not now

For: Always online, could also index what you share.

Against: Means writing an upload endpoint and auth into an app that is for something else; Taildrop to the builder plus serve gives the same result with no code.

KDE Connect No

For: kdeconnect 26.04 is in Guix.

Against: iOS client is limited (no background, little file sharing), and it pulls in KDE frameworks.

Syncthing No

For: In Guix, great laptop to builder.

Against: No official iOS client; third-party Mobius Sync is paid and limited by iOS background rules.

How Taildrop would fit

  • Receive. A home-shepherd-service runs a bb port of omarchy-tailscale-receive: tailscale file get --wait --conflict=rename into ~/Downloads/.taildrop, then hard-link into ~/Downloads under a free name and send a notification that dusk shows. Clicking it opens the file in oilfm or imv.
  • Send from oilfm. A SPC SPC palette command, Send to iPhone, runs taildrop-send with the marked files. The phone gets them in Files, Tailscale.
  • Send from anywhere. A leader entry, such as Cmd+Space then o then s (keys to be chosen with the keybindings skill), sends the newest screenshot or the clipboard image.
  • Share folder. tailscale serve --set-path /share ~/Share, so the phone opens the laptop's URL with /share in Safari. Optional: the same on the builder for an always-on drop.

Omarchy ideas, ranked

1. Taildrop receive service + send action

What: omarchy-tailscale-send / omarchy-tailscale-receive: a user service loops on tailscale file get --wait into a staging dir, renames into ~/Downloads without clobbering, and posts a notification (image preview, click opens). Send picks files and runs tailscale file cp.

You have: No. tailscale runs on the laptop, phone and builder; the operator setting is already set for this user (bbh-web.scm line 13 says so), so tailscale file get works without root.

Benefit: Phone to laptop in two taps from the iOS share sheet; laptop to phone from oilfm or a bind. No new app, no LAN needed, encrypted over the tailnet.

Effort: Small. One bb script (receive loop + send), one home-shepherd-service, a Hyprland bind, an oilfm palette command. All packages present.

Asahi: None known for aarch64; tailscale is your own package.

2. Clipboard history

What: Super+Ctrl+V opens a searchable text-and-image history (now in their Quickshell shell; earlier cliphist + walker).

You have: No history found. wl-clipboard is installed.

Benefit: Get back the thing you copied five copies ago, including screenshots.

Effort: Small. cliphist is in Guix; wl-paste --watch cliphist store as a home service; pick in the dusk launcher; wl-copy the result.

Asahi: None.

3. Capture extras: OCR, QR, color picker, annotate

What: Print-key family: region screenshot with notification and Edit button, OCR a region to the clipboard, decode a QR code, pick a color.

You have: Partly. Print saves a full shot and Shift+Print copies a region (hyprland.lua line 123). No notification, annotate, OCR or QR.

Benefit: OCR and QR come up often (error text in an image, a Wi-Fi or login QR). A notification with Open or Edit closes the loop.

Effort: Small. tesseract-ocr, zbar, hyprpicker and swappy are in Guix; Omasnap (their editor) is not, so use swappy. dusk already shows notifications.

Asahi: None expected.

4. Idle lock and lock-before-sleep

What: hypridle dims, locks and turns the screen off; sleep locks first and waits until the lock is secure; a toggle keeps the machine awake.

You have: No locker or idle daemon found in modules or hypr config (inferred from grep; tell me if dusk or zgui will own this).

Benefit: A laptop that is carried around should lock itself; a stay-awake toggle for long agent runs.

Effort: Medium. hypridle and hyprlock are in Guix; hyprlock needs a PAM entry on the system side (screen-locker-service-type), which means a make switch.

Asahi: Asahi suspend is s2idle; lock-before-sleep must hook elogind's PrepareForSleep, not systemd (inferred).

5. Screen recording toggle

What: Alt+Print starts or stops a recording of a region or screen, saves to ~/Videos and notifies.

You have: No.

Benefit: Short bug-repro clips to send to the phone or an issue (pairs with Taildrop).

Effort: Small. wf-recorder is in Guix. gpu-screen-recorder is too, but see the caveat.

Asahi: Asahi's GPU has no hardware video encoder exposed, so recording is software x264. Fine for short clips at 30 fps, heavier for long ones (inferred, untested).

6. Low-battery notice

What: omarchy-battery-low notifies once below a threshold and runs hooks.

You have: No (no bar either, so nothing shows the level).

Benefit: Avoid surprise shutdowns.

Effort: Tiny. A bb timer reading /sys/class/power_supply, notify-send into dusk.

Asahi: The Asahi battery is macsmc-battery (inferred name); read capacity and status files.

7. Toggle menu (night light, do not disturb, stay awake)

What: One menu and one command per switch: night light, silence notifications, idle, touchpad and more.

You have: Partly: keyleader and the leader grammar could host it; dusk has no DND state yet (inferred).

Benefit: Fewer one-off scripts; consistent leader entries.

Effort: Small to medium, mostly leader.edn entries. hyprsunset is in Guix.

Asahi: Night light needs color transforms on the Asahi DCP display driver; test hyprsunset before relying on it (unverified).

8. Web-app launchers

What: omarchy-webapp-install writes a desktop entry that runs the browser with --app=URL and an icon; launch-or-focus brings it forward.

You have: Partly: dusk launches desktop entries and chrome-unified exists; no app-mode entries found.

Benefit: Gmail, Calendar, the Tailscale admin, bbh web as their own windows with their own Hyprland rules.

Effort: Small: desktop entries in desktop.scm calling flatpak run com.google.Chrome --app=URL.

Asahi: Chrome is a flatpak on aarch64; app windows get class names like chrome-<host>__-Default, set rules on that (inferred).

9. Theme set with per-app templates

What: A theme dir per theme with colors and templates for terminal, bar, btop, browser, Herdr, Neovim; Super+Ctrl+T switches all at once.

You have: Partly: dusk has one theme map; Ghostty, Herdr, Doom each set colors on their own.

Benefit: One switch for light and dark across apps.

Effort: Medium: a theme edn plus a bb generator that writes Ghostty, Herdr and dusk colors, Doom loads a theme by name.

Asahi: None.

10. Status bar

What: A top bar (formerly Waybar, now their Quickshell shell) with clock, battery, network, updates, tailscale.

You have: No bar; possibly deliberate (inferred).

Benefit: Glanceable battery and network; an update badge.

Effort: Medium. waybar 0.15 and quickshell 0.3.2 are in Guix, but a dusk or zgui layer fits your stack better.

Asahi: None.

11. Keybinding cheat sheet menu

What: Super+K lists binds parsed from the config, searchable.

You have: Yes: keyguide, the keybindings reference and the leader hint panel.

Benefit: None new.

Effort: -

Asahi: -

You have: Bluetooth yes (bluetui package, connect-airpods). Wi-Fi: nmtui from NetworkManager (inferred); impala is iwd-only and not in Guix.

Benefit: Only a float rule and a bind.

Effort: Tiny.

Asahi: None.

13. Shell tools (starship, zoxide, eza, fzf)

You have: fish with your own setup.

Benefit: Low; zoxide is the one worth a look.

Effort: Tiny; all in Guix.

Asahi: None.

14. Fonts

What: JetBrainsMono Nerd Font as the system monospace; font menu.

You have: font-jetbrains-mono already.

Benefit: Low: Nerd glyphs only matter for icon-heavy TUIs.

Effort: Nerd Fonts are not in Guix main; would need a package.

Asahi: None.

15. Update and migration system

What: Release channels plus timestamped migration scripts run once per machine.

You have: Guix itself (declarative, rollbacks) plus your updates script.

Benefit: Low; Guix already solves this better. Only mutable stow configs could use a run-once migration.

Effort: -

Asahi: -
