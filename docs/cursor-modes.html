Cursor by editing mode (T223)

Goal. Wherever you edit modally, insert mode shows no cursor and normal mode shows an underscore. Visual, replace and operator-pending also show an underscore, since they act like normal mode. You asked for an invisible cursor in insert mode, and every place below follows that request.

The terminal stack

  • Ghostty already had cursor-style = underline, and shell integration's cursor feature is off (no-cursor), so shapes that programs request win. No change.
  • Herdr passes both the shape and the visibility through. I checked this with screenshots on the hidden display. No change.
  • ghostty-rex (rexg-render) handled the underscore and DECTCEM, but the Quint model and the Bombadil spec found five cursor bugs, now fixed. They included a frame that mixed an old cursor with a new overlay, a cursor that vanished until the pane printed something, and a stale cursor after a tab switch. The o bug (W301)

In the bbh Router's composer, o left the cursor visible on the new line until you typed. Terminal Emacs hides its cursor only as a side effect of drawing text, and ends each terminal update by showing it unless the window's cursor is off. The old fix turned the window's cursor off in post-command-hook, which runs after the command. But evil's -- INSERT -- echo updates the terminal at once, inside the command, and that update ended by showing the cursor. In the composer the redisplay after the command had nothing to draw, so nothing hid the cursor again. In a file buffer the line numbers or mode line usually redraw, which hid it by luck. Any way into insert state could hit it: o, O, a, A, i, I, gi, c, cc, C, s and S. Now cursor.el hides the cursor, and sends the hide itself, as soon as insert state starts, before anything can redisplay. On Escape it shows the cursor after the redisplay, so no frame shows the cursor next to the old -- INSERT -- mode line. The bug was in Emacs, not in Ghostty, Herdr or Rex, so the Quint model did not change. This Emacs is emacs-no-x, so GUI frames do not apply; a GUI Emacs draws cursor-type itself.

Where you will not see where you type

Insert mode now has no cursor anywhere. You can't see where text will land after you move with arrows or the mouse in insert mode, or in a long fish command line, or after you click into a Chrome field before you type. Press Escape to see the underscore again. This is what you asked for, so I did not soften it.

What to reload

  • rexg-render is a Guix package, so it needs make home (no sudo). After that, make refresh restarts the ghostty-rex client.
  • Doom: reload the config (M-x eng/reload-config) or restart Emacs. Neovim: restart it.
  • fish: new shells pick it up. In an open shell, run exec fish.
  • vimium-cljs: make refresh reloads the extension. Pages that are already open need a reload.
  • IdeaVim: :source ~/.ideavimrc or restart the IDE.
