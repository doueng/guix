Key bindings: Cmd+Space launcher, Alt+Space local prefix

How the Ghostty plus Rex setup works end to end, from Cmd+Return to the status line: ghostty-rex.html.

Design note for T208, written before the change. Two keys, one table.

Cmd+Space opens one launcher: the focused program's commands first, then every global command, each row with its key binding. Alt+Space is the local prefix: the same keys do the same thing in the focused program, such as Alt+Space t n for a new tab. Both come from desktop/configs/keybindings/leader.edn.

One source

leader.edn already holds one row per action with an implementation per context (:doom, :nvim, :idea, :herdr, :desktop, :chrome). The change adds:

  • A :rex implementation, so Ghostty-plus-Rex commands that Herdr lacks (tab move) can be declared. Everything else maps from :herdr as today.
  • :chrome becomes Chrome's local map (a chord sent to Chrome), no longer an override of a desktop action.
  • A t group, Tabs, with new, next, previous, close, rename, go to N and move.
  • :apps: which window class owns Alt+Space and how it gets there.

From that one file come: the launcher's local and global rows (desktop/bin/palette), the Hyprland binds (hypr/leader.lua: Super+Space, Alt+Space and Chrome's Alt+Space submaps), Herdr's leader menu (keyleader herdr), the Rex client's keymap (the sidecar's leader-commands under the alt+space prefix), and the editor leaders as before. Desktop chords and global launch commands stay in bindings.edn, which the launcher also lists; power commands join it.

Cmd+Space: the launcher

Super+Space no longer enters a Hyprland submap. It runs palette, which reads the focused window's class from hyprctl -j activewindow and shows one fuzzy list:

  1. Local, for the focused program: Chrome's Alt+Space map and Vimium keys; in a Herdr or Ghostty-plus-Rex window, the multiplexer's Alt+Space map, then the pane's program (fish history and functions, jjui keys); IntelliJ actions.
  2. Global: the old desktop leader actions, applications (Ghostty, Chrome, Chrome incognito, Emacs, bbh, Herdr), workspaces, windows, power (suspend, reboot, power off, log out, each asking again) and the guide tips.

Each row shows its keys. In Emacs, Emacs's own M-x list stays the list (it already caches thousands of commands), and the launcher appends the terminal and global rows to it, so one search still finds all three.

Old Cmd+Space sequences

Every old desktop sequence is a launcher shortcut. Typing its keys, with or without spaces, ranks that row first: Cmd+Space b b Enter, Cmd+Space . Enter, Cmd+Space tab3 Enter. The row shows them as ⌘␣ b b. One extra Enter is the price: running on the exact keys without Enter would fire o b while you were typing obsidian.

Chrome incognito, restored

Before the launcher, incognito sat two menus deep: Cmd+Space . opened custom-launcher, and its chrome-incognito row ran chrome-unified --incognito. The new list showed only the . row, so nothing named incognito appeared. It is now its own leader.edn binding, o n (Doom leaves SPC o n free):

  • Anywhere: Cmd+Space, then type on or incog, then Enter. The row reads Open Chrome incognito, ⌘␣ o n, and opens a new incognito window.
  • In Chrome: Alt+Space o n sends Chrome's own Ctrl+Shift+N. The Chrome launcher list shows this as a local row, which replaces the old palette.edn row New incognito window.

Nothing else was dropped. Every old leader.edn sequence and every bindings.edn entry still has a launcher row; three entries were only relabelled (Command palette is now Launcher, Herdr leader is now Local prefix, Editor terminal is now bbh). The only Hyprland bind removed was the old Alt+Space jump to Herdr, which the local prefix replaces. custom-launcher's other apps (Ghostty, Chrome, oilfm) still sit behind the . row, and Ghostty and Chrome also have their own rows.

The t keys follow Doom's SPC TAB workspace keys where they can (n, d, r, digits) and vim's h and l for direction, with Shift to move, as Ctrl+Alt+Shift+h/l moves windows. Herdr keeps its Ctrl+b prefix for its one-key natives (c, n, 1–9, f); Alt+Space covers everything the leader table names.

Rex has no Ctrl+b

In Ghostty-plus-Rex and rexmux, Alt+Space is the only prefix. Ctrl+b goes to the program in the pane, so fish moves back a character and Emacs gets C-b. Every command Rex had under Ctrl+b is a leader.edn row: the Herdr rows Rex maps, plus Rex-only rows with :rex (u, U, i, ?, w w, w H J K L, o g, s b, TAB r). The Rex sidecar binds them under Alt+Space and the launcher lists them with those keys, both from that file. Cmd+Y sends Alt+Space s l to the Rex window and still Ctrl+b f to Herdr.

Tests

  • make lint runs the bb keybinding tests: grammar, generated Alt+Space routing and Chrome submaps, launcher entries and shortcut ranking, Herdr tab actions, Rex tab commands.
  • Ghostty-plus-Rex live test on the hidden test display: Alt+Space t n opens a tab; the launcher opens in a Dusk on that display, filters, runs a local command (new tab) and a global one (open Ghostty). Every command Rex had under Ctrl+b runs from its Alt+Space keys, and Ctrl+b reaches fish in a pane. rexmux's e2e and Bombadil specs press the same keys, and ctrlBIsNoPrefix checks that Ctrl+b opens no which-key.
  • palette-test.clj: the launcher lists Open Chrome incognito with Cmd+Space o n in every context, choosing it runs chrome-unified --incognito, and Chrome's Alt+Space o n sends Ctrl+Shift+N. Live on the hidden test display, that argv opened one incognito Chrome window, and vimium-cljs keys typed with wtype worked there: j, G, gg scrolled and f showed hints.
  • make hypr-nested-check: Super+Space runs the launcher, Alt+Space routes by class.
