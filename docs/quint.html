Quint replaces TLA+ in this repo

Done: every TLA+ spec in the repo is now Quint, and TLA+ and tla2tools are gone. The four specs (bbh's Workflow, Effects and Super, and Rexmux) and their 12 TLC configs became four .qnt files with one instance module per old cfg. Each instance has the same distinct-state count under TLC as the TLA+ had, and every rule gives the same result. The Quint language server runs in Doom, and Babashka gets Quint the way it already gets TLC, Bombadil and Rex: a library that runs the CLI and returns EDN. Section 4 asks whether to move these specs to Choreo next. The answer is no.

1. The migration

Files: desktop/build/bbh/verify/quint/{workflow,effects,super}.qnt and desktop/build/rexmux/verify/quint/rexmux.qnt, which replaces the earlier partial connect.qnt. Each project's verify/quint/checks.edn replaces the cfg files: per model, its invariants, its temporal properties and its state count. The count is checked on every run, so the equivalence keeps being checked and a change to a model's state space shows up as a failure.

Apalache also checks the Quint (not the TLA+). A bounded quint verify to 6 steps holds for one invariant of each spec (connect, link, finish, serial, cancel), taking 11 to 27 s each. It is too slow to be the gate here: these specs interleave many small steps, which is where TLC is strongest.

How liveness checking differs from TLC

  • Same engine, so the same verdicts. Exhaustive checking, liveness included, still uses TLC: the TLC that ships inside the Apalache jar that Quint already carries, run on the TLA+ that quint compile generates. quint verify with Apalache refuses temporal properties, and quint run only samples traces against invariants. So liveness is proved by TLC alone, as before.
  • Fairness is written inside the property. TLA+ had Spec == Init /\ [][Next]_vars /\ Fairness. Quint has no Spec formula, so each property reads fairness implies ..., where fairness is a conjunction of weakFair(A, vars) and strongFair(A, vars). The mutants above that drop or weaken fairness break the same rules in both.
  • Named, and with loops. The old runner reported a broken liveness rule only as TLC. The new one names the rule, and returns the counterexample as data: {:states [...] :loop i}, a lasso back to state i. Lasso lengths differ from the old runs (for example 17 against 20 states), because TLC's liveness traces are not shortest and depend on how the spec is encoded. Safety traces have exactly the same length.
  • Action properties need a fix. A rule about one step is always(orKeep(P, vars)). Quint prints this as []([P]_vars), which TLC refuses, so the runner rewrites it to [][P]_vars before running TLC.

What Quint cannot express

  • No CHOOSE. Rexmux picked some pane with CHOOSE and Super picked the least ready Worker. Panes, streams and Workers are now ints, and the choice is the least by fold. This only renames things, so the state counts still match exactly.
  • No ENABLED in an invariant. None of these specs used it.
  • No Spec formula and no model values or symmetry sets in a cfg. Constants come from instance modules (import rexmux(NPanes = 2, ...).*). None of these specs used symmetry.
  • next(s).field is refused by Quint's effect checker. Write next(s.field) instead.
  • Nothing else blocked a port, and no rule was weakened.

Removed: the TLA+ and cfg files, bbh.tla and rexmux.tla, the verify:tla tasks, tla2tools in Home, and the checks.edn rules that used them. The verify-bbh-state-machines skill, both READMEs, desktop/build/bbh/doc/super-state-machine.html, the Rust and Clojure comments that named the TLA+ actions, and the property tests now point at the Quint. Older dated audits in docs/ still mention TLA+ as it was then, and I left them as they are.

3. Quint in Babashka

Here like the other languages means this: the repo has no pods. External tools are wrapped as babashka.process calls that return EDN, as bbh.tla did for TLC. So Quint got the same treatment: desktop/build/quint, a library on bbh's classpath, available as quint in every Worker REPL.

  • (quint/typecheck f), (quint/test f opts), (quint/run f opts), (quint/verify f opts) and (quint/model-check f main {:invariants .. :properties ..}) each return EDN. A trace is a vector of {var value} maps: sets as sets, maps as maps, records as keyword maps, and sum types as :Idle or [:Busy 2].
  • (quint/repl f main), (quint/repl-eval r "step") and (quint/repl-stop r) keep a live quint repl open, so an agent can step a model by hand.
  • quint.checks runs a checks.edn and powers bb verify:quint in both projects.

4. Should these specs move to Choreo?

Recommendation: migrate none of them. Choreo is built for N similar nodes that broadcast votes into an ever-growing pool of messages, as in consensus protocols. Only one of these specs passes messages between processes. I ported that one: it checks the same states, but it came out a third longer, it splits one atomic step across a process and a framework hook, and Apalache cannot check it. The other specs are a single store or a single controller, and Choreo has no place for them. Revisit Choreo for a new spec of several peer processes exchanging messages.

What Choreo is

  • measured A single file of Quint, choreo.qnt (291 lines) plus Quint's spells helper library, that you copy next to your spec and import as import choreo(processes = NODES) as choreo. It is not on npm and has no releases or tags. Its repository has 134 commits since June 2025, the last on 2026-06-23. It has five examples, four of them consensus or commit protocols (Tendermint, MonadBFT, Alpenglow, two-phase commit) plus an ATM distributed lock. Its CI only runs quint test and quint run --max-samples 20, so nothing there model-checks.
  • measured Model: one state variable s holding each process's local state, a set of messages per process, events (for timeouts), and shared extensions. A process is a function from its local context to a set of transitions, each a new local state plus effects: Broadcast, Send, TriggerEvent or a CustomEffect you apply to the whole state yourself. choreo::step picks a process and one of its transitions. Messages are a pool that a process receives from but never removes, which is cheap and correct for quorums of votes. The cue pattern pairs a listen function with an act function and gives tests like "p1".with_cue(listen, msg).perform(act).
  • measured Quint version: none is stated. Everything works on our Quint 0.34.0: typecheck, quint test, quint run, and TLC through quint.core/model-check, including fairness and liveness. TLC checks Choreo's two-phase-commit example in 99 states.
  • measured Apalache does not work. With Quint 0.34.0 and Apalache 0.62.4, quint verify stops with A typed declaration …choreo::s was transformed to an untyped expression. This happens on Choreo's own two-phase-commit example, on my port, and on the port with Choreo's unused display variable removed. The original link model passes the same check.

Which spec fits

rexmux linkWindow and sidecar exchange numbered messages over two FIFO pipes, the sidecar crashes, and the watchdog restarts it.The best fit, so I ported it (below).
rexmux connectThe client's attempts and the server's answers, with attempt ids reused once nothing names them, late answers, and a server stop that closes every socket at once.inferred Poor. Before reusing an id, the client must check that the server has nothing in flight for it, which is the server's state, not the client's. A reused id needs old answers deleted, but Choreo never removes messages. And a server stop changes both sides in one step. All three need a CustomEffect that edits the global state, which bypasses Choreo's model.
rexmux streams, agentsPane, stream and agent bookkeeping, and an event queue folded in order.inferred Poor: the event queue has to stay in order, while Choreo's messages are an unordered pool. Most of it is not message passing at all.

bbh workflowConcurrent wf attest calls read and append to one journal under a lock.inferred None: this is shared memory. In Choreo the journal would have to sit in extensions, which every process can read, and that undoes the point of using Choreo.

measured Same behaviour, not just the same count. I dumped every state TLC reaches in both models and mapped each to the same view: counters, open requests, answers, whether the sidecar is up, and the undelivered messages of each pipe in number order. The two sets are equal, with 205 states and nothing in one but not the other. The current link instance reports 615 because it has NStreams = 1, so a pane stream can be idle, connecting or live alongside the link, and 3 × 205 = 615. With NStreams = 0 it is 205.

inferred State space: the message pool adds no states here. Each pipe numbers its messages, so the delivered messages left in the pool follow from the counters, and the crash has to clear the pool anyway because numbering starts again. TLC's time is about the same; startup dominates at these sizes. Simulation is about 1.5 times slower, from the extra layers of functions and records.

inferred Readability. Choreo helps in one way: each step is a pure function from one process's view to its next state and messages, and the tests read step_with(BB, crash). Four things are worse.

  • The window's invoke needs to know whether the sidecar is up, and the watchdog's restart has to reset the sidecar's counters. A process can neither read nor write another's state, so bbUp moves into the shared extensions, and restart becomes a CustomEffect that edits the sidecar from outside. The rule that a restart happens in one step is now split across a transition and an effect handler.
  • A FIFO pipe becomes a pool filtered by n == got + 1. Pool contents stay after delivery, so the invariant about pipe order must first drop what was already delivered.
  • Both roles share one state record, and every transition starts with process_id == WIN or BB.
  • Fairness is stated per listener with weakFair(step_with(BB, bb_receive), choreo::s), which is fine, but every variable is the one s. TLC traces print all of it as a single nested value.
The port's source
// The rexmux sidecar link (rexmux.qnt, module link) ported to Choreo.
// Two processes: the window and the sidecar. Each numbers its messages from
// 1 and a receiver delivers the next number only. The sidecar can crash; the
// window's watchdog restarts it, which empties both pipes, starts both
// numberings again and fails every waiting request.
module link_choreo {
  import basicSpells.* from "spells/basicSpells"
  import choreo(processes = NODES) as choreo from "./choreo"

  const MaxReq: int
  const MaxRestarts: int

  type Node = str
  pure val WIN = "win"
  pure val BB = "bb"
  pure val NODES = Set(WIN, BB)

  // A request id, or the attention set.
  type Body = Req(int) | Att(Set[int])
  type Message = { n: int, body: Body }

  // One record for both roles; each uses its own fields.
  type StateFields = {
    sent: int, got: int,     // last number sent, last number delivered
    pending: Set[int],       // window: open requests
    answered: int -> int,    // window: answers per request
    nextReq: int,            // window
    winAtt: Set[int],        // window: the attention set it last received
    crashes: int,            // sidecar
  }
  // Both sides see whether the sidecar runs: the window by its watchdog.
  type Extensions = { bbUp: bool }
  type CustomEffects = Crash | Restart
  type Event = ()

  /* Boilerplate */
  type LocalState = choreo::LocalState[Node, StateFields]
  type LocalContext = choreo::LocalContext[Node, StateFields, Message, Event, Extensions]
  type Transition = choreo::Transition[Node, StateFields, Message, Event, CustomEffects]
  type GlobalContext = choreo::GlobalContext[Node, StateFields, Message, Event, Extensions]
  /* End of boilerplate */

  val reqIds = 1.to(MaxReq)

  // The window asks the sidecar to run a command.
  pure def invoke(ctx: LocalContext): Set[Transition] = {
    val s = ctx.state
    if (s.process_id == WIN and ctx.extensions.bbUp and s.nextReq <= MaxReq)
      Set({ post_state: { ...s, sent: s.sent + 1, pending: s.pending.setAdd(s.nextReq), nextReq: s.nextReq + 1 },
            effects: Set(choreo::Send({ to: BB, message: { n: s.sent + 1, body: Req(s.nextReq) } })) })
    else Set()
  }

  // The next message in this process's pipe.
  pure def listen_next(ctx: LocalContext): Set[Message] =
    ctx.messages.filter(m => m.n == ctx.state.got + 1)

  // The sidecar takes the next message and replies.
  pure def bb_reply(ctx: LocalContext, m: Message): Transition = {
    val s = ctx.state
    { post_state: { ...s, got: m.n, sent: s.sent + 1 },
      effects: Set(choreo::Send({ to: WIN, message: { n: s.sent + 1, body: m.body } })) }
  }
  pure def bb_receive(ctx: LocalContext): Set[Transition] =
    if (ctx.state.process_id == BB and ctx.extensions.bbUp) choreo::cue(ctx, listen_next, bb_reply) else Set()

  // The window takes the next message from the sidecar.
  pure def win_take(ctx: LocalContext, m: Message): Transition = {
    val s = { ...ctx.state, got: m.n }
    match m.body {
      | Req(r) => { post_state: { ...s, answered: s.answered.setBy(r, k => k + 1), pending: s.pending.exclude(Set(r)) },
                    effects: Set() }
      | Att(a) => { post_state: { ...s, winAtt: a }, effects: Set() }
    }
  }
  pure def win_receive(ctx: LocalContext): Set[Transition] =
    if (ctx.state.process_id == WIN) choreo::cue(ctx, listen_next, win_take) else Set()

  // The sidecar dies; nothing in the pipes survives.
  pure def crash(ctx: LocalContext): Set[Transition] = {
    val s = ctx.state
    if (s.process_id == BB and ctx.extensions.bbUp and s.crashes < MaxRestarts)
      Set({ post_state: { ...s, crashes: s.crashes + 1 }, effects: Set(choreo::CustomEffect(Crash)) })
    else Set()
  }

  // The watchdog restarts it: both numberings start again, the window fails
  // every waiting request, and the sidecar first sends its attention set.
  pure def restart(ctx: LocalContext): Set[Transition] = {
    val s = ctx.state
    if (s.process_id == WIN and not(ctx.extensions.bbUp))
      Set({ post_state: { ...s, sent: 0, got: 0, pending: Set(),
                          answered: s.answered.keys().mapBy(r => if (s.pending.contains(r)) s.answered.get(r) + 1 else s.answered.get(r)) },
            effects: Set(choreo::CustomEffect(Restart),
                         choreo::Send({ to: WIN, message: { n: 1, body: Att(Set()) } })) })
    else Set()
  }

  pure def apply_custom_effect(env: GlobalContext, e: CustomEffects): GlobalContext = match e {
    | Crash => { ...env, extensions: { bbUp: false }, messages: env.messages.transformValues(_ => Set()) }
    | Restart => { ...env, extensions: { bbUp: true },
                   system: env.system.setBy(BB, b => { ...b, sent: 1, got: 0 }) }
  }

  pure def main_listener(ctx: LocalContext): Set[Transition] =
    Set(invoke(ctx), bb_receive(ctx), win_receive(ctx), crash(ctx), restart(ctx)).flatten()

  pure def initialize(n: Node): LocalState =
    { process_id: n, sent: 0, got: 0, pending: Set(), answered: reqIds.mapBy(_ => 0), nextReq: 1,
      winAtt: Set(), crashes: 0 }

  action init = choreo::init({
    system: NODES.mapBy(n => initialize(n)),
    messages: NODES.mapBy(_ => Set()),
    events: NODES.mapBy(_ => Set()),
    extensions: { bbUp: true },
  })

  action step = choreo::step(main_listener, apply_custom_effect)
  action step_with(v: Node, l: LocalContext => Set[Transition]): bool = choreo::step_with(v, l, apply_custom_effect)

  temporal fairness = and {
    weakFair(step_with(BB, bb_receive), choreo::s),
    weakFair(step_with(WIN, win_receive), choreo::s),
    weakFair(step_with(WIN, restart), choreo::s),
  }

  // Rules
  def win = choreo::s.system.get(WIN)
  def bb = choreo::s.system.get(BB)
  // What a process has not delivered yet is numbered in order after what it has.
  def inOrderAt(v: Node): bool = {
    val left = choreo::s.messages.get(v).filter(m => m.n > choreo::s.system.get(v).got).map(m => m.n)
    left == (choreo::s.system.get(v).got + 1).to(choreo::s.system.get(v).got + left.size())
      and choreo::s.messages.get(v).filter(m => m.n > choreo::s.system.get(v).got).size() == left.size()
  }

  val typeOK = win.pending.subseteq(reqIds)
  val noDuplicateReply = reqIds.forall(r => win.answered.get(r) <= 1)
  val answeredNotPending = win.pending.forall(r => win.answered.get(r) == 0)
  val inOrder = inOrderAt(BB) and inOrderAt(WIN)

  temporal everyRequestAnswered = fairness implies
    reqIds.forall(r => always(win.pending.contains(r) implies eventually(not(win.pending.contains(r)))))
}

module link {
  import link_choreo(MaxReq = 3, MaxRestarts = 2).*

  // A crash fails the waiting request once, and its late reply never comes.
  run crashAnswersOnceTest =
    init
      .then(step_with(WIN, invoke)).then(step_with(BB, bb_receive))
      .then(step_with(BB, crash)).then(step_with(WIN, restart))
      .expect(win.answered.get(1) == 1 and win.pending == Set())
}
