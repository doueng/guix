rexmux vs Herdr: feature parity

How the Ghostty plus Rex setup works end to end, from Cmd+Return to the status line: ghostty-rex.html.

Outcome. rexmux now covers what you use in Herdr. Cmd+Enter opened a dead shell because rexmux showed the newest Rex session, a stray test session whose shell had exited; it now makes and shows its own main session. Checking parity turned up two more bugs, both fixed: Super+Return/E/D/G never switched tabs under rex, and after a reboot split or renamed panes came back in bash. Herdr is still the default.

Try it

cd ~/guix
make mux MUX=rex     # build rexmux, switch, home-apply, reload Hyprland
# Super+B or Super+Return opens it
make mux MUX=herdr   # back to Herdr

Your Rex server still holds the stray spike and w242 sessions. rexmux ignores them; rex kill w242 and rex kill spike remove them.

How it was tested

Everything ran on the hidden test display (headless sway) against a throwaway Rex server with its own HOME and socket, never your screen or your Rex. Stubs stood in for emacs-bbh, pi and jjui. make rexmux-verify runs it all: the sidecar against a live server, Bombadil over rexmux tty (rexmux.ts for panes and agents, startup.ts for startup tabs and tiny fingers), and the 24-check window e2e.
