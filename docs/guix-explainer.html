1. The whole picture

manual: Introduction

You never write to /gnu/store yourself. You describe what you want in Scheme in /home/engstrand/guix. The guix command turns that description into exact build recipes, and guix-daemon, the only process allowed to write to the store, makes them real by downloading or building. What you actually use (your PATH, /etc, the running system) are symlinks into the store. Changing the system means building new store items and moving a link.

2. The store: content named by its inputs

manual: The Storemanual: Invoking guix gc

On Guix System, /gnu/store is mounted read-only and owned by root. Only the daemon remounts it to add items. Nothing is changed in place: an upgrade adds a new item next to the old one. Each item records which other items it references, found by scanning its files for store paths. That makes the store a dependency graph. The live flatpak refers to 40-odd items, for example 0mcy4zq0…-glibc-2.41, bnc3s7ly…-glib-2.86.5, 1ny35lgp…-bubblewrap-0.13.0 and 2z53gn84…-libostree-2025.1 (guix gc --references).

Why a store path can vanish: T137

3. Packages, derivations, outputs and the build daemon

manual: Defining Packagesmanual: Derivationsmanual: Invoking guix daemonmanual: Build Environment Setup

Builds are deterministic in their inputs. Same derivation, same output path, wherever it is built: the laptop, guix-builder or ci.guix.gnu.org. That is what makes substitutes and offloading safe.

4. Substitutes: download instead of build

manual: Substitutesmanual: Substitute Authenticationmanual: Substitute Server Authorizationmanual: Getting Substitutes from Other Servers

Your order comes from substitute-urls in modules/engstrand/system/asahi.scm lines 199–202. guix-builder comes first because it holds what make prebuild built, including the custom kernel. The Asahi channel's own service is deleted (line 188) so this list alone decides the order. Trusted keys are %asahi-substitute-keys, the builder's builder-signing.pub and Guix's default keys for ci and bordeaux (lines 193–196). The daemon reads them from /etc/guix/acl, which activation writes. Narinfo URL and compression above are illustrative.

6. Profiles and generations

manual: Featuresmanual: Invoking guix packagemanual: Invoking guix system

A profile is itself a store item, a union of symlinks to packages plus a manifest. A generation is a numbered link to one profile. Generation links live under /var/guix/profiles, which is a GC root, so every generation you keep keeps its whole closure alive. Live chains on 2026-11-10: system 90–94, guix-home 55–56, current-guix 7–8.

7. Channels, guix pull, time-machine and inferiors

manual: Channelsmanual: Channel Authenticationmanual: Invoking guix pullmanual: Invoking guix time machinemanual: Inferiorsmanual: Replicating Guix

~/.cache/guix holds authentication checkouts http locate substitute: git clones, the authenticated-commit cache and the substitute and narinfo cache. Deleting it is safe but makes the next pull slow. guix pull generations are rolled back with guix pull --roll-back. Inferiors let Scheme code use packages from another Guix revision. Time-machine is the command-line form.

8. Guix System: operating-system, services, Shepherd

manual: Using the Configuration Systemmanual: operating system Referencemanual: Service Compositionmanual: Shepherd Servicesmanual: Invoking guix system

Where your config lives. desktop/system.scm (4 lines) → %familiar-config in modules/engstrand/config.scm → make-base-os in modules/engstrand/system/asahi.scm (kernel asahi-linux-keyd, Btrfs root with compress=zstd:1, the m1n1 bootloader, guix-daemon settings, earlyoom, zram) plus the feature-familiar-* modules in modules/engstrand/features/. rde (rde-config) turns features into system and home services.

Shepherd is PID 1. Each Shepherd service in the graph becomes one service it starts, stops and supervises (sudo herd status). Activation runs at boot and on every reconfigure. It is what makes /etc, accounts and one-off setup match the generation.

9. Guix Home

manual: Home Configurationmanual: Home Servicesmanual: Invoking guix home

This setup can deploy Home two ways, and they can disagree. make switch activates the home built into the OS. make home-apply runs guix home reconfigure desktop/home.scm, which makes guix-home generations (56 now). Today ~/.guix-home names the system's build, wvdl8kl4…-home, while guix-home-56-link names 33hj18yq…-home. Whichever ran last wins. The other generation stays a GC root until make gc deletes it.

10. Garbage collection and roots

manual: Invoking guix gcmanual: Invoking guix daemon

Store use on 2026-11-10: 65 GB used of 108 GB. Inspect before deleting: guix gc --list-roots, guix gc --referrers PATH (who keeps this alive?), guix gc --derivers PATH, guix size PATH. To keep a build result, guix build -r LINK adds an indirect root under /var/guix/gcroots/auto.

11. Offload and remote builds

manual: Daemon Offload Setup

With --max-jobs=0 the laptop's daemon starts no ordinary build itself. When substitutes miss, it calls the offload hook. That hook reads /etc/guix/machines.scm, generated from build-machines in asahi.scm lines 57–69 (guix-builder.tailbf68ad.ts.net, port 2222, user offload, one build at a time). It copies the missing inputs over SSH, builds there and copies the outputs back, signed by the builder. make switch JOBS=1 builds locally once when the builder is down.

The full story, with failure modes and the nightly prebuild: remote-builder-explainer.html

14. Glossary

store item
A file or directory under /gnu/store, named HASH-name. Immutable once written. manual: The Store
derivation (.drv)
The low-level build recipe: builder, arguments, environment, inputs and output paths.manual: Derivations
output
A store item a derivation produces: out, and for some packages lib, doc, debug…manual: Packages with Multiple Outputs
closure
A store item plus everything it references, transitively. What a substitute or a copy must carry.manual: Invoking guix gc
realise
Make a derivation's outputs exist: already there, substitute, or build.manual: Derivations
substitute
A prebuilt output (nar + signed narinfo) downloaded instead of building.manual: Substitutes
nar / narinfo
Normalized archive of a store item / the signed text describing it (hash, size, references).manual: Invoking guix archive
authorized key
A signing key listed in /etc/guix/acl; substitutes must be signed by one.manual: Substitute Server Authorization
graft
Rewrite references in existing outputs to a fixed replacement package, without rebuilding.manual: Security Updates
profile
A store item that unions packages into one tree (bin/, share/…) plus a manifest.manual: Features
generation
A numbered symlink to one version of a profile; switching and rolling back move it.manual: Features
GC root
A symlink under /var/guix/gcroots (directly or via profiles or auto/) that protects its closure.manual: Invoking guix gc
channel
A git repo of Guix modules (guix, asahi, rde), pinned by commit and authenticated by introduction.manual: Channels
time-machine / inferior
Run, or load as an object, a different Guix revision alongside yours.manual: Inferiors
operating-system
The record describing the whole OS: kernel, bootloader, file systems, users, packages, services.manual: operating system Reference
service type / extension
A service contributes to others it extends; the graph folds into one system.manual: Service Composition
Shepherd
Guix's init and service manager: PID 1 for the system, and a user instance for Home.manual: Shepherd Services
activation
The script a generation runs to make it live: /etc, accounts, links, snippets.manual: Service Reference
home-environment
The Guix Home counterpart of operating-system, for one user's ~.manual: Home Configuration
offload
Send a build over SSH to a machine listed in /etc/guix/machines.scm.manual: Daemon Offload Setup
rde feature
rde's unit of config: a feature adds system and home services together; rde-config folds them. rde
