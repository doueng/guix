P1

FindingVerdictWhat changed
(1) Connection attempt and close race in rexgHolds. Fixed in yrlyptsv Confirmed. A duplicate :connected was closed with ws/close!, its reader then put [:rex srv [:closed ..]], and :closed dissoc'd the live connection without closing it. Now each try is an attempt gen, and the model has a :connecting state. [:connect srv gen], [:connected srv gen c], [:connect-failed srv gen why] and [:rex srv gen msg] all name their attempt. The model adopts, closes or drops sockets with [:conn/adopt|close|drop srv gen], so main decides nothing. A stale :connected is closed. A stale :connect-failed or :closed changes nothing. main drops responses and events from any connection that is not live.
Found while fixing it: connect! starts its reader before main queues :connected, so a server that dies right after the welcome queues :closed first. The model ignored that close and then went up on a dead socket. Now a close of the current try fails the try.
Tests. a-duplicate-is-closed-and-its-late-close-changes-nothing covers two attempts that both succeed: one is rejected, and its close arrives after the other is live. It also covers a late close after a reconnect. The property (below, P2.3) fails on both old behaviours. Rexmux.tla now has attempt ids that are reused only when nothing names them, a set of answers that can arrive in any order, a Late action for an attempt the model stopped waiting for, and the new invariants UpIsLive and NoLeak. TLC fails UpIsLive when the close-before-connected fix is removed, and fails UpIsLive and NoLeak when a stale :connected is adopted.
(2) sidecar/perform! has no error isolationHolds. Fixed in xkyuoruq Confirmed for both shells and for :bbh/say. Each local op now runs in its own try. A failure is logged with (:log io): to stderr in the rexmux sidecar, and to REXG_LOG in ghostty-rex, whose stderr is the terminal. A spawn carries :for, its invoke's id, and that invoke's reply becomes {:op :reply :id :seq :error}. It keeps its :seq, so numbering stays contiguous, and a failed bbh say no longer says “Sent:”. perform! never throws, so the state and the messages stay in step. The new test a-spawn-that-throws-answers-its-invoke-with-an-error-and-loses-nothing makes :spawn! and :notify throw. It asserts that the error reply arrives, that a later ping and a Rex event still arrive, and that the messages are numbered 1..n with no gap.

P2

FindingVerdictWhat changed
(3) connection_test simulation gapHolds. Fixed in yrlyptsvRewritten as a state-machine property over attempts with identities. Connects stay in flight until the server answers (:answer). The server can die and close every socket it has (:die), answer and then die before the :connected is queued (:answer-die), or drop the live connection (:hangup). An answer already handled can arrive again (:replay). A socket the client closes reports its own close. Per step, the property checks that the client is never stranded and that the model is up exactly on the adopted connection. At the end, the live connection is the only open socket. The unused :during key is gone.
(4) voice_property_test flakiness and review draftsHolds. Fixed in zmkxutpwAsks are now numbered a1, a2, … in each generated thread, so their ids are distinct. On review drafts I decided that voice may not send a draft that picks a review ask. Sending it is an approval made by voice, and the module's rule is that voice never approves. send-refusal now refuses action and review picks, and an explicit test covers both, plus a review ask the draft does not pick.
(5) :agent/new-worktree runs jj during interpretationHolds. Fixed in qxsprzpvThe command returns [:workspace/create {:cwd :name :command :session}]. perform! runs jj and returns a :workspace/created result (or its error). The new sidecar/settle! delivers that result back, and the invoke is answered then, once, with the new window or the error. Both shells drive the sidecar through settle!. Side fix: jj's output used to reach the rexmux sidecar's stdout, which is the protocol pipe. It is now captured.
(6) Outbox property does not inject crashesHolds. Fixed in tvkpxyoqEach round now generates a crash point, runs only that prefix of the pass, and replans. Sessions take mail as take-mail! does: a message the transcript already holds is deleted unread. The property checks that a row's message id never changes, that each message is delivered at most once, and that every row this run sent ends done after it was read, which catches a lost message. A mutation that records the send before writing the file fails the loss check.
