Chrome without the address bar, with tabs on the side

Answer

Recommended: fake fullscreen plus a tab list in the side panel. Hyprland tells Chrome it is fullscreen while the window stays tiled. Chrome then hides the tab strip and the whole toolbar, but keeps the side panel. A small chrome.sidePanel tab list (a prototype took about 30 lines) shows the tabs on the side. F11 brings the address bar back and hides it again, and a plain Esc does not leave this mode.

Chrome 157's own vertical tabs work, but they don't solve this: the toolbar stays, and in fullscreen the vertical tabs are hidden too. No flag or policy hides only the toolbar.

What I tested

Tested on Chrome 157.0.8103.38 (flatpak, aarch64) and Hyprland 0.55.4 with the Lua config. The test Chrome used a throwaway profile on a virtual headless monitor, so your daily profile and screen were untouched. The profile was deleted afterwards.

Option 1: fake fullscreen plus a side-panel tab list

The Hyprland dispatcher hl.dsp.window.fullscreen_state({ internal = 0, client = 2 }) leaves the window tiled (with gaps and borders) while Chrome believes it is fullscreen. The side panel stays visible, on the left or right as set under Appearance, Side panel position. As a window rule it applies at launch and does not steal focus. I tested this live:

hl.window_rule({ name = "chrome-no-toolbar",
  match = { class = "google-chrome" },
  fullscreen_state = "0 2" })
  • F11 asks Chrome to leave fullscreen, so the toolbar comes back while the window stays tiled. Pressing F11 again hides it. Measured state: [0,2] → [0,0] → [0,2].
  • A short Esc does not leave fullscreen (still [0,2]), which matters with Vimium and vim habits.
  • When fullscreen is toggled at runtime, Chrome shows a press and hold Esc bubble for a few seconds. With the launch rule it does not appear.
  • Ctrl+L to the Vomnibar should be unaffected because it is the extension's own key. I did not test vimium-cljs in the test profile.
  • The side panel is per window and is not reopened after a restart. One keypress (an extension command) opens it again.

Which tab list?

The Chrome Web Store has several side-panel tab extensions: Vertical Tabs in Side Panel (guokai.dev, 4.1), Tab Shelf (tabshelf.com, 4.4), Sidearc (4.6), Vertical SidePanel Tab Group Manager (4.7) and others. All of them need the tabs permission, which can read every URL and title. Many add workspaces, AI grouping, sync or accounts. I did not install any of them. They all rely on the same chrome.sidePanel mechanism I tested with the prototype.

Pick: add the panel to vimium-cljs. It already holds tabs, so this adds no new trust and no third party. The work is one side_panel entry, the sidePanel permission, a small panel page that lists, activates and closes tabs and follows tab events, and a command to open the panel. The prototype's panel.js:

const l = document.getElementById('l');
async function render() {
  const w = await chrome.windows.getCurrent();
  const tabs = await chrome.tabs.query({ windowId: w.id });
  l.replaceChildren(...tabs.map(t => {
    const d = document.createElement('div');
    d.className = 't' + (t.active ? ' a' : '');
    const i = document.createElement('img');
    i.src = t.favIconUrl || '';
    const s = document.createElement('span');
    s.textContent = t.title || t.url;
    d.append(i, s);
    d.onclick = () => chrome.tabs.update(t.id, { active: true });
    d.onauxclick = e => { if (e.button === 1) chrome.tabs.remove(t.id); };
    return d;
  }));
}
for (const e of ['onCreated', 'onRemoved', 'onUpdated', 'onActivated', 'onMoved', 'onAttached', 'onDetached'])
  chrome.tabs[e].addListener(render);
render();

Option 2: Chrome's built-in vertical tabs

In Chrome 157 these are a regular setting with no flag: Settings, Appearance, Tab position: Vertical (pref vertical_tabs.enabled). The tabs move into a left column, and the toolbar with the omnibox moves to the right of that column.

I searched chrome://flags (649 flags) for vertical, immersive, compact, toolbar, hide, tab strip, side panel, fullscreen. Only follow-up flags showed up (tab-strip-unification, side-panel-flyover-animation, webui-toolbar). Nothing hides the omnibox or gives a compact or immersive mode on Linux. Enterprise policies have no setting for this either. --kiosk and --app remove the tab UI completely.
