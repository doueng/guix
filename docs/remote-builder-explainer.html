3. The updates script

From desktop/bin/updates (stowed as ~/.local/bin/updates) and desktop/bin/builder-prebuild, after T41, T77, T128 and T134. Scroll down: the step in the middle of the screen lights up, and its column shows where it runs.

Report mode: updates, updates list, updates refresh. It only reads; nothing in the repo changes.
Apply mode: updates apply. It edits pins, prebuilds on the builder and checks the laptop would only download. It never pulls or switches for you.

channel: git ls-remote branch heads, with guix held at 704ad8c for rde. github: gh api releases/latest or commits/HEAD for each upstream-binary package. release and latest: the GitHub release, else the newest version tag, for Guix packages with a GitHub source. upstream and skills: git fetch into ~/.cache/checkouts. flatpak: the Flathub API. doom: ls-remote. lazy: headless lazy.check.

updates, the *-refresh functions
guix source: evaluate the bumped channels

guix time-machine -C bumped.scm lists the package versions a bump would bring. While the builder answers, updates adds --max-jobs=0 and the builder + bordeaux substitute URLs, so building Guix for the new pins happens on the builder.

updates, the *-apply! functions
Builder up?

curl --max-time 10 …:8080/nix-cache-info. Yes: go on to make prebuild. No: it warns prebuild skipped and prints the rebuild steps with JOBS=1, which build on the laptop.

updates, builder-up? and prebuild!
make prebuild → builder-prebuild build

Pushes jj's @ commit (even an undescribed updates edit) to prebuild@guix-builder:guix.git as refs/heads/prebuild, plus any file:// channels as channel-NAME. Then it runs ssh prebuild@guix-builder prebuild run REV and waits.

Makefile, prebuild · builder-prebuild, push-and-build
prebuild run REV

Takes a lock, writes :running to status.edn, checks out REV and points file:// channel URLs at guix.git. Then it builds, all through guix time-machine at the pinned channels: describe (what make pull needs), the system, Home and every desktop/build/*/manifest.scm, each with a GC root.

builder-prebuild, run-prebuild
Bake the publish cache, keep 3 revisions

Requests localhost:8080/HASH.narinfo for every item in the closure, so publish compresses it before the laptop asks. It prunes roots to the last 3 revisions and records :ok.

builder-prebuild, run-prebuild (the bake) and prune-roots
make builder-check

Publish reachable? Prebuild status? Then guix time-machine … system build --dry-run and the same for Home, at the channels.scm pins with builder + bordeaux. It fails if anything other than local-build derivations (boot, activate, profiles) would build on the laptop.

builder-prebuild, check and dry-run-builds

4. The trust chain

Two separate kinds of trust. Guix signing keys decide which store items a daemon accepts; ssh keys decide who may log in. Firewalls decide who can connect at all.

The risk this accepts: because the laptop trusts builder-signing.pub, root on the builder can put store items on the laptop. Tailnet-only access, nftables, no passwords and a single-purpose host limit that risk. Removing the key from asahi.scm revokes it. The secret halves live only on their machines: /etc/guix/signing-key.sec on each, and ~/.config/guix-builder/ on the laptop. modules/engstrand/builder/README.md lists every .pub file.

5. Day to day

The same workflow as the Day to day section of remote-builder-plan.md (T134). For details and the cheat sheet, see W139's overview. T134 in flux

Edit config, switch

Edit, make verify, commit. For a big change run make prebuild first, then make home-apply / make switch. Anything missing offloads by itself.

Updates

updates refresh · updates · updates apply · then the make steps it prints · commit.

Guix lags a release

updates apply release/NAME adds it to latest.scm; latest/NAME bumps it later. Delete the line once Guix catches up.

Nightly, 03:00 / 05:00

Rebuilds the last pushed revision unless it is already :ok; then gc to 20 GB free.

Prebuild failed

A notification or updates names the revision and log in /var/lib/prebuild/logs. Fix, commit, make prebuild.

Builder down

Rebuild steps print with JOBS=1. Check tailscale status, make builder-check, the Hetzner console.

Builder OS

After make pull: make builder-deploy (guix deploy over the tailnet). Roll back with guix system roll-back as root.

6. The feed reader lives here too

T143 moved the reader off the laptop. Open https://guix-builder.tailbf68ad.ts.net/ on the phone. The old asahi-guix URL is gone. modules/engstrand/system/reader.scm · desktop/bin/reader-push

Services

reader (wrangler + workerd on 127.0.0.1:8787), reader-suggester (8788) and the reader-serve one-shot, which restates tailscale serve at boot and deploy. They run as the user reader, respawn, and log to /var/log/reader*.log.

Update the code

npm run build in the checkout if the UI changed, then make reader-push. Check with make reader-status.

State

/var/lib/reader/state: about 20 MB of SQLite. Pushing code never touches it, and guix gc ignores /var/lib.

Cost

No extra money. About 700 MB of RAM and 290 MB of disk, idle between page loads. A big build slows a refresh but doesn't stop the reader.

7. The second brain lives here too

T150 put the second brain (T147) on the builder. Open https://guix-builder.tailbf68ad.ts.net:8443/ on the phone; only your tailnet login gets in. modules/engstrand/system/second-brain.scm · modules/engstrand/packages/second-brain.scm · desktop/bin/second-brain-push

Service

second-brain (bb on 127.0.0.1:8790) and the second-brain-serve one-shot for tailscale serve on 8443. User second-brain, respawns, logs to /var/log/second-brain.log. A Guix package, so a deploy ships the code; herd restart second-brain picks it up.

Chrome sync

A Home timer on the laptop pushes Chrome's bookmarks every hour when they changed, over ssh with a key that can only run the importer. Safari and X exports: second-brain-push html|x-likes|x-export FILE.

Nightly, 21:30

Fetches up to 1500 new pages, rewrites the markdown tree and backs up the db, at nice 19 and idle I/O with a 3 h cap, well before the 03:00 prebuild.

Data

/var/lib/second-brain: brain.db, raw imports, seven daily backups. make second-brain-status shows the counts.
