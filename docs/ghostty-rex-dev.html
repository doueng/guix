ghostty-rex: develop, reload, test and troubleshoot

For working on MUX=ghostty-rex, the opt-in Rex window. Herdr stays the default. What the parts are, how to edit and reload each one, where the logs are, how to switch and roll back, and what to do when something breaks.

The client runs bb straight from the checkout at /home/engstrand/guix, so an edited .clj needs no build. Rex holds the sessions, panes and programs, so a client restart loses nothing.

Edit and reload

Quick reload (T210). After editing bb code or config.edn, run 
make ghostty-rex-reload
or choose Client: reload its bb code and config in M-x (Alt+Space Space). The client closes its Rex connection and replaces itself with a fresh bb attach on the same session in the same window, in about a second. Under the hood it runs rex -C ghostty-rex do mx.client.reload.

The C renderer

  1. make ghostty-rex compiles target/rexg-render in under a second. Unit tests and make ghostty-rex-verify use that build, and verify rebuilds it when csrc/ is newer.
  2. The window uses the Guix rexg-render on PATH first. To try a checkout build, start a window from a terminal with REXG_RENDER=/home/engstrand/guix/desktop/build/ghostty-rex/target/rexg-render /home/engstrand/guix/desktop/bin/ghostty-rex
  3. To install it for every window, run make home-apply (or the full make switch), then make ghostty-rex-reload.

Keys

Alt+Space is the local prefix, and leader.edn's :rex actions run under it; see /home/engstrand/guix/docs/keybindings.html. A leader.edn edit takes effect after a reload.

The T210 checks in verify: after a reboot no tab shows a typed exec line; the window survives its server stopping and a server from another build taking over, with a red status while it retries, and typing works again; SIGTERM ends the client and rexg-render with no kill -9; reload brings up a new client on the same session and drops the old one; a pane that sends ESC [ ?25 l gets no cursor. Bombadil's restored spec runs startup.ts with its new noTypedExecLine property on a session Rex brought back as bare bash.

Live tests stay off your screen and your server. Everything runs in test-display (a headless sway) and a throwaway Rex server under /tmp. Until T210, a test's cleanup ran rex server stop, which ignores REX_SERVER and stopped the live server. The harness now names its server with -S.

Logs

  • Client log. Set REXG_LOG when starting a window from a terminal: REXG_LOG=/tmp/rexg.log /home/engstrand/guix/desktop/bin/ghostty-rex. It records keys, every request the client sends (out), lost and reconnects, rex server start results, and quit with its reason.
  • Rex server log. /home/engstrand/.local/state/rex/servers/ has one <hash>.log per server. Grep it for Rex server ready, stopped and not replaying creation options on restore. rex server status says whether a server runs and where.
  • Clients. rex client list shows who is attached; two ghostty-rex entries make rex -C ghostty-rex ambiguous.
  • Test runs. With --keep, the run directory under /tmp/ghostty-rex-e2e-* has client.log, client.err, ghostty.log, results.edn and a screenshot per step.

Switch and roll back

make mux MUX=ghostty-rex   # opt in: home-apply and a Hyprland reload
make mux MUX=herdr         # back to the default
guix home roll-back        # also restores the previous choice

Rex keeps its sessions through a switch, a make switch and a reboot. After a reboot or a server restart, Rex restores every tab as your login shell from /etc/passwd (bash) and drops the fish and program options. The client then opens a fresh block running fish, or the tab's program (pi gets pi --continue), in its place and closes the bash block. Nothing is typed, so no exec fish -l line appears.

Troubleshooting

Status line red: local not connected, reconnecting
The control connection dropped. The client retries every 0.25 s, backing off to 4 s, and runs rex server start for the local server when nothing answers; that command does nothing when a server is already up and replaces a dead socket. When the server is back the window reattaches to the session it showed, with no kill needed. If it stays red, check rex server status and the server log.
A window that won't close
SIGTERM ends both the client and rexg-render (the e2e checks it), so pkill -f 'ghostty-rex/bb.edn attach' without -9 is enough. Closing the Ghostty window does the same.
A tab shows bash, or a restored tab lacks its program
The client revives restored tabs only for the startup session it finds itself; a window opened with --session skips this. A reload keeps its session and skips this; close the window and open it again (Super+B) to go through it.
rexg-render is missing
Run make home-apply with MUX=ghostty-rex, or make ghostty-rex for the checkout build.
A fix doesn't show up
bb and config edits need a reload; C edits need make home-apply (or REXG_RENDER) and then a reload; a Ghostty config edit needs Ctrl+Shift+Alt+R.
