Own the Asahi kernel, drop the asahi-guix channel

Goal. Own the kernel and boot chain in this repo, and build the system with only the guix and rde channels. Nothing is reconfigured or rebooted until you do it yourself.

The kernel

  • Source: https://github.com/AsahiLinux/linux tag asahi-7.2.15-1. This is the tag running now, so it is known to boot. To bump it, edit the version, revision and hash in modules/engstrand/asahi/kernel.scm.
  • Config: modules/engstrand/asahi/kernel.config is a defconfig fragment with comments. At build time Guix copies arch/arm64/configs/defconfig, applies the fragment, runs make guix_defconfig, then runs verify-config, which fails if olddefconfig drops any line. To change an option, add a line such as CONFIG_FOO=m or # CONFIG_FOO is not set.
  • Starting point: the channel's option list, translated line for line, plus your CONFIG_INPUT_UINPUT=m. It replaces two layers of config (the channel's, then your keyd wrapper) with one.
  • uname -r stays 7.2.15-asahi, so module paths and the ANE module are unchanged.

Risks

RiskMitigation
Unbootable machinem1n1 and u-boot are vendored without change, so their store paths match the running ones. The installer keeps /boot/efi/m1n1/boot.bin.old. GRUB lists every earlier generation, and the current one stays there for rollback. The new kernel's .config and module list are compared with the running kernel before you switch.
Firmware regression (Wi-Fi, Bluetooth)The firmware activation code is copied byte for byte apart from module names. After the switch, check that /run/asahi-guix/firmware exists and that Wi-Fi comes up.
GPU regressionMesa is the same upstream package. DRM_ASAHI, APPLEDRM and the kernel-module-loader list are unchanged.
Falling behind on updatesYou now pick the Asahi tag yourself. Check https://github.com/AsahiLinux/linux/tags, bump the version and hash, and build on guix-builder. A build fails loudly if a config option disappears. m1n1 and u-boot bump the same way in boot.scm.
Builds no longer come from substitutes.asahi-guix.orgguix-builder builds them; the kernel takes about an hour there.

Changing the kernel

  • An option: edit modules/engstrand/asahi/kernel.config, then run make build (the compile runs on guix-builder) and bb desktop/build/asahi/check-kernel.bb to see the difference from the booted kernel.
  • A new Asahi release: set %version, %revision and %hash in modules/engstrand/asahi/kernel.scm. To get the hash, run guix hash -rx on a checkout of the tag, or set a wrong hash and copy the right one from the build error. If verify-config reports a dropped option, delete or fix that line in kernel.config.
  • Faster builds: the channel listed non-Apple SoCs and errata to switch off but never applied them, so the kernel still compiles drivers for Tegra, Rockchip, Qualcomm and others. Adding those # CONFIG_ARCH_... is not set lines would shorten the build. This change leaves them out so the first switch changes nothing.

Switching (you run this)

  1. cd /home/engstrand/guix && make pull. This removes the asahi channel from your Guix; make switch refuses to run while the pulled Guix differs from channels.scm.
  2. make switch, then reboot into the default entry.
  3. Check: uname -r prints 7.2.15-asahi, /proc/cmdline names linux-asahi-7.2.15-1, ls /run/asahi-guix/firmware lists firmware, Wi-Fi and Bluetooth connect, the speakers play, and bb desktop/build/asahi/check-kernel.bb exits 0.

Rollback

  • It does not boot: in the GRUB menu pick GNU system, old configurations, then the previous generation (GNU with Asahi-Linux-Keyd 7.2.15-1). m1n1, u-boot and the DTBs are the same bytes, so the earlier stages are unaffected.
  • It boots but something is wrong: sudo guix system roll-back, then reboot. Then guix pull --roll-back brings the asahi channel back into your Guix, and you revert the commit with jj.
  • guix-builder also stops using the asahi substitute server once you next run make builder-deploy. Nothing needs to happen there before your switch.
