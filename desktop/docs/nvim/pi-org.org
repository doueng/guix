#+TITLE: pi-org.nvim
#+OPTIONS: toc:2

A Neovim frontend for the [[https://github.com/earendil-works/pi][pi]] AI coding agent, written in Fennel.

Unlike [[https://github.com/aldoborrero/pi-agent.nvim][aldoborrero/pi-agent.nvim]] (which wraps pi's interactive TUI in a Neovim
terminal buffer), pi-org drives pi headlessly via its [[https://github.com/earendil-works/pi/blob/main/docs/rpc.md][RPC protocol]]
(=pi --mode rpc=) and renders the conversation in org-mode using
[[https://github.com/nvim-orgmode/orgmode][nvim-orgmode]]. Both the transcript and the input buffer are =org= filetype
buffers, so you get folding, syntax highlighting, source blocks, and TODO
state for free.

* Architecture

pi-org is a set of Fennel modules under =fnl/pi-org/=:

- =config.fnl= :: defaults + validation
- =jsonl.fnl= :: strict LF-only JSONL framing (mirrors pi's =jsonl.ts=; avoids
  the U+2028/U+2029 splitting that Neovim's default reader would do)
- =rpc.fnl= :: spawns =pi --mode rpc= via =jobstart=, sends commands on stdin,
  dispatches events/responses on stdout, correlates request/response by =id=
- =render.fnl= :: turns agent events (=message_update= / =tool_execution_*= /
  =compaction_end= / ...) into org-mode text appended to the transcript
  buffer; streaming text deltas are rewritten in place between two extmarks
- =session.fnl= :: owns the transcript buffer, the input buffer, the window
  layout (split or float), buffer-local keymaps, and the RPC/renderer wiring
- =init.fnl= :: =setup=, user commands, global toggle keymap

* Usage

Opening =:PiOrg= takes over the current window for the transcript and
splits off a slim input pane below it (default 1/4 of the screen height) —
two panes total, not three. Toggling =:PiOrg= off (or =:PiOrgClose=)
restores the buffer that was in the window before pi-org opened. The cursor
is placed in the input pane in insert mode, ready to type.

A status footer (winbar) sits above the panes showing the active agent mode,
model, and thinking level, plus a braille spinner (=⠹ working…=) while a turn
is streaming. Line wrapping is enabled in both panes only while pi-org is
open and restored to your prior setting on close.

| Command       | Description                                  |
|---------------+----------------------------------------------|
| =:PiOrg=      | Toggle the pi-org transcript + input windows |
| =:PiOrgClose= | Stop pi and close the session                |
| =:PiOrgSubmit=| Submit the current input buffer              |

Default keymaps (configurable via =setup=):

| Key          | Mode | Action              |
|--------------+------+---------------------|
| =<leader>po= | n    | Toggle pi-org       |
| =<C-n>=      | i, n | Submit prompt       |
| =<C-c>=      | i, n | Abort running turn  |
| =<leader>pn= | n    | New session         |
| =<leader>pm= | n    | Cycle model         |

* Launching from the shell

A fish function =piorg= (in =~/.config/fish/functions/piorg.fish=) launches
Neovim with the frontend already open:

#+BEGIN_SRC fish
function piorg --description 'Launch Neovim with the pi-org org-mode agent frontend open'
    # --cmd runs before config load so the VimEnter autocmd sees the guard
    # and skips auto-opening the snacks explorer sidebar.
    command nvim --cmd "let g:pi_org_skip_explorer = 1" $argv -c "PiOrg"
end
#+END_SRC

Use it like =piorg= (opens in =$PWD=) or =piorg some/dir=. The function sets
=g:pi_org_skip_explorer= so the config's auto-open file-tree (snacks explorer)
stays out of the way. The underlying shell command is =nvim -c "PiOrg"=.

* Configuration

#+BEGIN_SRC fennel
(let [pi-org (require :pi-org)]
  (pi-org.setup
    {:command "pi"
     :args ["--no-session"]
     :window {:position :botright     ; or :topleft :vertical :float
              :split_ratio 0.6
              :input_ratio 0.25}
     :org {:show_thinking true
           :show_tool_args true
           :show_tool_results true
           :wrap_width nil}           ; nil = no hard wrap
     :keymaps {:submit "<C-n>"
               :abort "<C-c>"
               :toggle "<leader>po"}}))
#+END_SRC

* Rendering conventions

- User prompt :: =* User= headline, body = the prompt text
- Assistant turn :: =** Assistant= subheadline with streamed text below
- Thinking :: a =#+BEGIN_SRC text= block (foldable)
- Tool calls :: =*** Tool: <name>= with a =#+BEGIN_SRC <lang>= block of args
- Tool results :: =#+BEGIN_EXAMPLE= block replacing the args block
- Compaction / retries :: italic =/.../= notice lines

* Development

Set =vim.g.pi_org_debug = 1= to trace every raw stdout chunk and decoded
JSONL line on stderr (useful when debugging the RPC stream).

Files compile with =fennel --compile= and format with =fnlfmt=:

#+BEGIN_SRC bash
for f in fnl/pi-org/*.fnl fnl/plugins/pi-org.fnl; do
  fennel --compile "$f" >/dev/null && fnlfmt "$f"
done
#+END_SRC

The modules are loaded at runtime by the =fennel= searcher installed in
=init.fnl=, so no build step is required for iteration (only =init.fnl= is
compiled to =init.lua= at Nix build time via =mkFennelBootstrap=).
