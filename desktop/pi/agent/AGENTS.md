# Pi tool workflows

- Use `codemode` for built-in, extension, and MCP tool calls. Codemode accepts only Clojure through SCI. Settings enable `only` mode. Do not use direct MCP calls, `tool_search`, standalone MCP clients, or an MCP adapter to bypass it.
- For this SCI codemode, read the absolute README path in the `codemode` description instead of the installed Pi `docs/codemode.md`. The installed document describes the disabled JavaScript evaluator. Follow its local links for async behavior, structured reads, and persistent helpers.
- Discover unlisted tools with `(await (catalog/search "query"))`. Inspect `(await (catalog/describe id))` or `(await (catalog/namespace name))` before calling them. Use the returned canonical ID with `catalog/invoke` or its generated `tools/<name>` symbol. Never guess tool names or arguments.
- Keep MCP servers on the built-in integration with `exposure: "codemode"`. Preserve deliberate `hidden` tools. Avoid `direct` or `deferred` exposure overrides. Keep credentials and private server configuration out of repositories.
- Batch independent reads, searches, and diagnostics with `(await (all-settled [...]))`. Reduce results before printing. Print relevant evidence and individual failures, not entire large results or repeated schemas. Examine files with `fs/read`. Discover files with `search/files`, `fs/list`, and `fs/glob`. Print strings with `text`. Do not print image payloads.
- Run programs on the host; write programs in SCI. Prefer semantic `jj`, `guix`, `repo`, `make`, `fs`, `sys`, and `search` functions. Use `search/text` and `search/files` backed by Pi search, not an `rg` process. There is no `git` namespace or generic process runner. `tools/bash` is an escape hatch for genuinely shell-specific work or host programs without a domain namespace. Keep ordinary parsing, filtering, grouping, sorting, joins, and aggregation in SCI. Do not generate temporary Python, JavaScript, shell, or Babashka programs for such analysis. Project-owned programs, tests, builds, and heavyweight or domain-specific software remain legitimate host commands.
- Named domain operations use semantic options. For example, `(await (jj/log {:revisions "@" :limit 10}))`, `(await (guix/build {:file "package.scm"}))`, `(await (make/run "target"))`, and `(await (repo/pi-sci-test))`. Collection results have `:items` and `:truncated`. `fs/read` has clean `:text`, line metadata, and `:next_line`. `fs/exists?` returns a boolean. Command actions have `:ok` and exit metadata; use `(result/check r)` to check success. `result/stdout!` is for textual command results, not structured reads. Use `fs/read-json` for complete parsed JSON in `:value`. Do not parse display-limited `tools/read` output. Use `fs/read-jsonl` with field projections for session records. Follow `:next_cursor` until nil before claiming complete coverage, and report `:value_truncated` fields as excerpts. Check truncation before complete-data analysis. Collect independent effects first, await them together, then reduce in SCI. Consider `defsession` after repeating a nontrivial pattern; do not persist one-off transforms.
- Await every tool call. Keep dependent operations and shared-state mutations sequential. A failed script does not undo earlier calls. Codemode is orchestration, not a subagent. Existing tool guards still apply.
- Bash returns a map. Inspect `:exit_code`, `:output`, `:truncated`, and `:full_output_path`. `text` prints bash and command results as a status line plus raw output. MCP returns its CallToolResult. Check `:isError` and use `:structuredContent` or `:content`. Other tools may return strings. Forward image blocks with `image`, never print base64.
- Use `models/classify` and `models/generate-images` inside codemode for ad hoc classifier and image tasks. Discover available models first. Check `:stopReason` and `:errorMessage`. Keep specialized extension tools when they provide validation, policy, or session state.
- Aliases `tools`, `catalog`, `models`, `json`, `str`, and `set` are prebound. Tool arguments are Clojure maps. Field spelling stays exact. Async helper functions need `^:async`. Ordinary `def` and `defn` last for one invocation. Explicit top-level `defsession` persists literal constants or functions in `session`. Use `session/definitions`, `session/source`, and `session/forget` to inspect or remove them. Functions cannot capture invocation-local bindings. Code and `store` changes commit together only on success. Use `store`, `load`, and `unstore` for small JSON-compatible branch-local task data. Store cursors and compact summaries, not raw transcripts. One value is limited to 262144 JSON characters and the whole store to 1048576. Do not retry external effects after a commit conflict.
- Shell scripts and autoresearch hooks run outside codemode and cannot access its bindings. Keep their CLI implementations. Fetch session MCP evidence through codemode before a run when needed.
