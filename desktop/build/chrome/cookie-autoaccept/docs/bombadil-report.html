Phase 2: hiding before paint and answering early

The extension now also runs an early script at document_start in every frame of an enabled site. It hides 699 known banner selectors with opacity 0 until the page has been answered. In the top frame, it writes the consent value that OneTrust, Cookiebot, Didomi, Usercentrics or InMobi (Quantcast) Choice reads, as soon as that CMP's script tag appears. Per-site blocking of CMP scripts through declarativeNetRequest is optional and off by default. The README lists the trade-offs.

Four properties were added. Their checks run against fixtures whose CMP stand-in scripts load from the real CMP host names, which Chrome maps to the local server, plus a OneTrust page that is not idle for 1.5 s and a bakery page whose hero only looks like a banner.

A fourth injected bug, registering the early script on disabled sites too, was stopped by the harness's own check of the registration before Bombadil started. measured

Finding 5: a late banner could be seen for one frame. In a sweep of every fixture (40 s each), late-onetrust.html failed cmpBannerNeverShows with seed 924754453. Its OneTrust banner arrives 6 s after load, after the prehide was released. The early script hid a newly added banner again only in its next animation frame callback. So an earlier callback in that frame, here the probe's frame counter, saw the banner at full opacity. A banner added from a ResizeObserver callback, which runs after a frame's animation callbacks and before its paint, would also have painted for one frame. Fix: the mutation observer now matches each added subtree against the selectors in its own callback, a microtask of the task that added the banner. The cost is a matches and querySelectorAll on each added subtree, for 30 s. Regression test: a new e2e check appends a OneTrust root after the release and reads its opacity one microtask later. It got 1 on the old code and gets 0 now. Afterwards, the failing trace replays clean, late-onetrust passes on four seeds, and a 300 s run over the whole site (177 states, 58 page loads, seven of the eight mode, disabled and blocking combinations) passes. measured

Phase 3: the same extension in ClojureScript

The extension was ported to ClojureScript (shadow-cljs 3.5.11) in three commits, each loadable from dist/: a build into dist/, then the worker, popup, policy and CMP table, then the content scripts. spec.ts and probe.js did not change. The harness now loads dist/ and finds the popup and the mode file by their new paths.

  • Same behavior: all 36 unit tests were ported to cljs.test assertion for assertion and pass. A one-off differential run fed the old JavaScript and the port the same random inputs, including malformed settings and messages. It covered settings, reports through random message sequences, popup lines, badges, CMP consent values and host matching (123,166 checks), plus 40,000 banner and button cases for the fallback heuristics. The only difference was the intended one: the early script now loads two files instead of four. The prehide selector list, now built at compile time, is identical to the generated file it replaces. measured
  • Bombadil on the cljs build: a sweep of all 26 top-level fixtures (40 s each) and a 300 s run over the whole site pass. e2e passes 16 of 16, including a new check that per-site blocking installs and removes its rule. measured
  • One regression caught during the port, before any commit: the worker lost the CMP hosts for the blocking rule, because the compiler dropped an import that was used only for its side effect. No Bombadil run had turned blocking on yet, and no e2e test covered it. The new e2e check covers it now.
  • Sizes: the document_start script went from 36.0 KB (11.3 KB gzipped, four files) to 26.6 KB (9.6 KB), and the fallback from 11.6 KB to 7.3 KB. The content scripts use interop only. A first build was 115 KB, because = pulls all of cljs.core into a bundle. identical? compiles to ===, as the JavaScript did, and keeps it out. The worker (124 KB) and popup (112 KB) carry cljs.core for their maps; neither is on a page's load path. measured

Specs

These properties are checked on every state. Each one reads facts that a probe script gathers inside every fixture page and frame: untrusted clicks (an extension's el.click()), consent choices made through the fixture's handler, marks the fallback left, autoconsent's style elements, whether the consent UI is visible, and what blocks the page.

PropertyRule
bannerGoesAwayOn an enabled site, a visible consent banner is gone within 15 s of being seen. A pay-or-consent wall is exempt in reject mode, since it can only be paid or accepted.
disabledSiteUntouchedOn a disabled site: no script clicks or decisions, no fallback marks, no autoconsent styles, and no consent UI hidden without the user's choice.
rejectNeverAcceptsIn reject mode, no script click on an accept button and no script accepted decision, including inside frames.
clicksStayInConsentUiEvery script click lands inside consent UI and never on a link that navigates or on a form's submit button. No script form submit.
pageStaysUsableWith no banner visible, nothing fixed covers half the viewport, and html and body are not scroll-locked, for more than 3 s.
nonConsentUiStaysThe newsletter box and the mail sign-up stay visible.
popupTellsTheTruthWhen the real popup is opened, its status line matches the page: Off exactly when disabled; Accepted only in accept mode with evidence; Rejected only in reject mode with no accept; Hid N equals the hidden marks; No cookie popup seen only if nothing was done.

Actions: in-page clicks, link clicks, scrolling, back, forward, reload and wait. Dwells of 2 to 4.5 s, weighted up while a page is younger than 12 s, give late banners and the fallback's retries time to happen. The harness opens the real popup through chrome.action.openPopup to read it, toggle the site, or switch accept and reject; these choices are weighted so that disabled sites get re-enabled.

Fixtures

Nineteen top-level pages and two frame pages are served on localhost and 127.0.0.1 with no network: OneTrust, OneTrust loaded 6 s late, Cookiebot (old and current template), Didomi, Quantcast, TrustArc, Usercentrics in shadow DOM, Sourcepoint in a cross-origin frame, an unknown TCF v2 CMP with __tcfapi, a pay-or-consent frame, generic banners (plain, late in shadow DOM, late in light DOM at 9 s), two modals with a backdrop and scroll lock, a newsletter box, a mail sign-up form, and a page with no banner. Seven of these are new; the rest are the e2e fixtures, now marked with data-consent-ui or data-keep.

Run time and cost

  • Final 10-minute run: 363 states, 93 page loads, 16 of the 19 top-level fixtures, all four mode and site combinations, and 23 popup reads. measured
  • About one action per 1.6 s, because dwells dominate. One Chrome runs at a time, plus Bombadil, a 14 MB static binary.
  • npm run bombadil defaults to 300 s. It is not part of npm test or the e2e run.

Chromium on aarch64 Guix

ungoogled-chromium 156 is in Guix, but no substitute server had it for aarch64. guix build --dry-run would build Chromium and clang 23 from source, which takes many hours on this machine. measured The harness therefore runs the flatpak Chrome headless with a throwaway profile and read-only access to the repo. It loads the extension over the DevTools pipe (Extensions.loadUnpacked) and gives Bombadil a debugging port. Your daily Chrome profile is not touched. CHROME=/path/to/chromium switches to any Chromium binary.

Reproducing

npm run bombadil                          # 300 s over the whole site
npm run bombadil -- --time 600 --seed 7   # starts in reject mode with localhost disabled
npm run bombadil -- --page sourcepoint.html
npm run bombadil -- --reproduce /tmp/cookie-autoaccept-trace-XXXX

On failure the harness prints the violated property with the page facts, the seed and the trace directory. Bombadil 0.7.10 has no seed of its own: its trace is the replay, and the seed fixes the starting settings. The replay of finding 4's trace passed once the fix was in.

Limits

  • Exploration is random, so a short run can miss a combination. The sweep runs, 45 s per fixture with --page, are what covered every page.
  • The probe sees only open shadow roots, and frames only through what they post to their parent.
  • Bombadil cuts a custom action off at about 5 s, so a long stay is several dwells in a row.
