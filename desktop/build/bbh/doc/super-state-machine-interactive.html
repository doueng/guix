The loop: commands in, events out, state folded

One writer, one transaction. store/commit! runs a command in one SQLite transaction: if its id was seen, it returns the stored result and writes nothing (an idempotency key, so a signal is consumed once); else model/decide returns events, they are appended with a seq, a time and a format version, and the result is stored under the id.
State is a fold. At start the controller replays the log from the newest snapshot (store/replay). Old events are upcast to today's format (model/upcast), and retired kinds such as the old lease events fold to nothing. fold stamps :state-at whenever a Worker changes state, which is what durable timers count from.
Who may do what. The owner may run anything. The Router may run thread!, start-worker!, steer!, cancel!, note!, milestone!. A Worker may ask!, note!, milestone!, answered!, finish-worker!, only on its own thread and itself. The controller runs the rest (grants).
Activities outside the fold. Side effects (workspaces, wf runs, Emacs buffers, mailbox files, job kills, landing) run in super.clj before or after a commit, each idempotent by a name derived from the Worker or row, and each recorded by a command with a fixed id, so a crash at any point repeats nothing twice.

Pick a machine, then tap a state: its outgoing transitions turn blue, incoming purple, and the panel lists each with its event, command, who runs it, the guard and the code. Tap a numbered transition for just that one. Dashed states are derived by reads, never stored.

Router calls and the events they make

The Router is one long-lived conversation. Its verbs (bbh.super.verbs/router) are requests to the controller's handle, which commits a command and then runs what it owes. Play it jumps to the step in a scenario.

What changed since the static page

  • T154, Temporal-style. The state is rebuilt from the event log alone; events carry a format version and are upcast; snapshots bound replay; timers are durable (model/due over :state-at) and fire as commands with derived ids, so they commit once; finish effects are activities with retries (effect-tries 3) and fixed ids.
  • T52, the person's message as authority. The Router's start, steer and cancel can name the message they act on (:for "o12"); the log records its origin. :for is a record, not a lease, and the old Worker lease events are retired.
  • T110, sessions and resources. Sessions of ended Workers are reaped once idle or after a 10 minute grace; heavy commands share one machine-wide slot; each health pass logs memory, swap and sessions (machine-observed).
  • T161 to T163, Emacs. Transcript buffers stay responsive, a dying bbh process gets a new session, a turn's error no longer leaves the shell busy, leftover mailbox timers are swept, and Workers cannot reach the live bbh-super Emacs.
  • T146, per-Worker model. start-worker! :model, allowlisted by policy :worker-models; a replacing Worker keeps the replaced one's.

The rules in each machine's invariants are model-checked with TLA+ in desktop/build/bbh/verify/tla/ (Super.tla, Effects.tla, Workflow.tla; make test ONLY=bbh-state-machines).
