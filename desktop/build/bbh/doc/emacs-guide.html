1. Start it

Two Home Shepherd services run everything, and both start at login and respawn on their own:

  • bbh-super is the controller (bbh super serve): the SQLite store, the command socket, mailbox delivery and the phone website. Its log is ~/.local/state/bbh-super.log.
  • bbh-emacs runs the Emacs daemon named bbh-super (emacs --fg-daemon=bbh-super), which holds the Router, every Worker and the Inbox. Its log is ~/.local/state/bbh-emacs.log.

Note the names: herd restart bbh-super restarts the controller, and herd restart bbh-emacs restarts the Emacs daemon. Both are user services, so you run herd without sudo.

  1. Press the Herdr prefix, then t, or run bbh inbox in any terminal. Either one opens a terminal frame on the daemon (emacsclient -s bbh-super -t) showing the Inbox.
  2. Run herd status bbh-super bbh-emacs to check that both services are up.
  3. The controller starts the Router when none is running. If it doesn't, run bbh super start-router. That registers a new Router token and replaces any open Router session.

2. The Router and Worker buffers

Each session fills the frame, with its transcript (Router transcript, T12 title transcript) above a short composer. Opening the Router, a Worker or the Inbox first closes every other window. The composer opens in normal state (T28), so SPC leader keys work at once. Press i to type.

  • Router (buffer Router; SPC m r, C-c r or R in the Inbox). Sending here doesn't go straight to the session. It goes through bbh super say! with origin :emacs, so the controller numbers the message (oN) and the Router can start a Worker for it.
  • Workers (buffer T12 title; RET on a thread in the Inbox). What you send here goes straight to that Worker's session.
  • Composer (agent-shell's edit buffer). C-n sends in any state (Cmd+N through kanata), and C-c C-c and M-RET also send. RET inserts a newline, C-c C-k stops the turn, M-p/M-n walk the history and C-u/C-d page the transcript in normal state. g? lists the keys.

Routing with a thread handle: T12 …

Start a message to the Router with a thread handle to send it to that thread. T12, t12, T12: and the spoken tee twelve all work, and the handle is removed from the text:

  • If T12 has a running Worker, the text steers that Worker directly as [T12 from emacs] …, and the Router gets a one-line summary.
  • If T12 has no running Worker, the Router gets T12: … and decides what to do, for example starting a new Worker on the thread.
  • A handle for a thread that doesn't exist is refused, and Emacs shows the error. Your text stays in the composer.

Typing in a finished Worker's buffer also goes to the Router, prefixed About T12, whose Worker is finished:, so the Router can reopen the thread.

3. The Inbox

The Inbox opens as a split view (T86). *bbh threads* on the left lists one thread per line. *bbh inbox* on the right is an org outline (T82) of the selected thread: its open asks, its last eight progress events and a link to its Worker. A frame narrower than 110 columns puts the list above the thread. gv switches to the older single-buffer outline of every thread and back. Moving in the list redraws the right side at once, and the controller pushes changes, so you never need to refresh. gr reloads anyway.

Reading a line

●Waiting on you: an open ask (Stopped on you, Holding up work, Waiting on you), or a Worker waiting.
◐Working or queued.
✖Stuck: Needs attention (a failed Worker, an ended session, or a problem that needs a human).
✓Done or quiet.
•A change you haven't read yet. Opening the thread's Worker, or the thread on the phone, marks it read, and so does m without opening it. Read state is shared, so the phone and Emacs agree.

Each line shows the id, the title, the number of open asks (2?) and the age. Threads are grouped by section in this order: Stopped on you, Holding up work, Waiting on you, Needs attention, Sent, New, Working, Quiet, Archived. Within a section the newest (highest number) comes first (T99). Archived threads fold into one row, and RET on it shows or hides them. Long text wraps at the window and keeps its org indentation (T94).

What's waiting on you

  • The header line starts with bbh inbox · N need you.
  • The ● threads sort to the top. ]t and [t jump to the next or previous one and wrap around.
  • Only Stopped and Waiting asks raise a Herdr toast. Progress never does.
  • The header also shows old code: … while a bbh process still runs code older than the checkout.

4. Answering questions

Press o or TAB in the list to move to the thread, and o there to go back. C-h and C-l also move between the panes. The keys act on the ask under the cursor, or on the thread's newest open ask if the cursor isn't on one. Picks and typed answers are saved as a draft in the controller, which the phone shows too. Nothing reaches the Worker until you send.

  1. TAB folds and unfolds. On an ask it shows the folded Details, which hold the context and an evidence link (open the link with RET).
  2. 1–9 picks an option, and . picks the one marked (recommended). RET on an option line picks it too. The line then shows <- picked.
  3. i jumps into the ask's Answer heading in insert state, so you can answer in your own words. That heading is the only text you can edit. Leaving insert state saves your answer to the draft. r does the same, or on a thread with no open ask, prompts for a note.
  4. C-c C-c (also in insert state) or s sends the thread's picks, answers and note as one reply. In an Answer, C-n (Cmd+N through kanata) sends too, in insert and normal state; on any other line it is evil's C-n. S sends every thread's draft after one y/n question. C-c C-k discards the draft.
  5. A approves a review ask. Voice can never approve.

Inside an Answer body every key types normally. A reload while you type waits until you leave insert state, and it keeps your place, your folds and anything you haven't saved.

5. jjui on a thread: J

  • J (in the list or the thread) opens jjui on the thread's Worker workspace in a Herdr popup. Once the workspace is gone it opens the repo instead.
  • To close it, press q in jjui once (T93), or press gJ (SPC m J) in the Inbox.
  • Herdr shows one popup at a time. If the Inbox itself was a popup (prefix t), jjui replaces it, and quitting jjui brings back a fresh Inbox. Over an Inbox in an ordinary pane, quitting jjui just leaves you where you were. Pressing J again replaces jjui rather than stacking a second popup.
  • The popup puts ~/.local/bin first on its PATH so that jjui's diff preview can find pierre-diff-ansi (T84). See troubleshooting if the preview is blank.

6. Resume, archive, cancel, reopen

u resumeReopens the session of a Worker whose session ended, for example after a reboot or crash. It keeps the same conversation and wf run. The Worker is told to check its jobs, and after a reboot it is told which jobs died. Resume is refused if the session hasn't ended, if the wf run is missing, or if the Worker cap is full.
a archiveDismisses the open asks, tells the Worker, and cancels a Worker that is still queued. A running Worker carries on. An archived thread takes no new Workers, so start a new thread that says it continues the old one.
x cancelCancels the thread's Worker after a y/n question, whether the thread is archived or not.
m mark readClears the thread's • without opening its Worker. M marks every thread read and U marks the thread unread again. The phone shows the same.
D dismissCloses the asks and tells the Worker not to wait.
ReopenOpen the finished thread's buffer (RET) and type there. The text goes to the Router, which can start a new Worker on the thread. Or tell the Router T12 ….

7. Voice and phone

  • Hold Cmd+Shift+M and speak, then release M, Cmd or Shift. Hex transcribes and bbh say sends the text, and nothing is pasted, so it works whichever window has focus. Without a handle the words go to the Router, whatever the Inbox cursor is on (T34 fixed the stray T1: prefix). Start with a handle to act on a thread: “tee twelve, option two, send” picks option 2 on T12 and sends it, and “the recommended one” or an option's label also work. A spoken pick stays a draft until you say “send” or press s.
  • Cmd+M is plain dictation. It pastes at the cursor, so it suits an Answer body, the r prompt or a composer.
  • Phone: the website is served on 127.0.0.1:8766 and published over Tailscale at https://<node>.<tailnet>.ts.net:8443. It shows the same threads and drafts. A tap saves a pick, and Send sends it. The composer at the bottom of the list talks to the Router, and a leading T12 routes the message as in Emacs.

8. Clipboard

The kill ring and the Wayland clipboard are shared, including in the bbh-super daemon, which starts without WAYLAND_DISPLAY (T42). Emacs falls back to the wayland-N socket in XDG_RUNTIME_DIR, so evil y copies to the system clipboard and p pastes from it. Pasting over a visual selection keeps the clipboard. make clipboard-check tests the round trip.

10. Troubleshooting

A status looks stale (for example “waiting” while the Worker works)
Press gr. A hidden Inbox catches up as soon as a window shows it. If the header says reload failed: …, check herd status bbh-super. If it shows old code, the controller restarts once it is idle. A session that is busy in a turn counts as working even while an ask is open.
A message seems stuck
A Worker takes mail only between turns, and a turn can include a 10-minute job-wait. After 30 minutes in the mailbox the thread shows ✖ with “Delivery oN has waited … in its mailbox”. Open the Worker (RET). If its turn is hung, press C-c C-k in the composer. An idle shell wakes itself with [mail] every second. If Router messages fail with “Router: …”, check that the Router runs, or run bbh super start-router.
Dead Workers after a reboot
They show ✖ Needs attention with “Its session ended. Resume it with u …”. Press u on each one, or run bbh inbox resume T12. They keep their wf run, and the resume tells them which jobs the reboot killed.
The jjui preview pane is blank
The Herdr server's PATH lacks ~/.local/bin, where pierre-diff-ansi lives. herdr-jjui adds it, so check that the tool is installed (make pierre-diff-ansi) and run bb desktop/build/herdr/jjui/preview-check.bb to reproduce the popup's environment.
“The Router is not running” or “No buffer … is its Worker running?”
Run bbh super start-router. For a Worker, press u (resume).
