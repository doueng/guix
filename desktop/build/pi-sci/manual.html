SCI codemode technical manual

How the Clojure codemode extension for Pi works in this Guix configuration: how to use it, how to change it, and why it is built this way.

Overview

What the setup is, which versions it pins, and how to use this manual.

What SCI codemode is

SCI codemode replaces Pi's built-in JavaScript codemode tool with a Clojure interpreter. The model writes one Clojure program per tool call. The program calls Pi tools, waits for their results, transforms the data, and prints only what the model needs to see. Pi still executes every tool, applies every guard and hook, accounts for model usage, saves images, and persists branch-local state.

The interpreter is SCI (the Small Clojure Interpreter), compiled to JavaScript with ClojureScript and loaded into the QuickJS WebAssembly sandbox that Pi already uses for codemode. Nothing in Pi is patched or forked. The setup is an extension that registers a replacement tool definition around Pi's stock executor.

On top of the interpreter, the extension registers seven semantic domains: jj, guix, make, search, fs, sys, and repo. Each domain is one Pi tool with typed operations. Inside SCI the operations appear as functions such as (jj/log {:limit 5}) that return structured data instead of command-line text. Bash stays available as an escape hatch.

How this manual is organized

The manual has four parts. Each part does one job, so read the part that matches what you need now.

  • Tutorial. A guided first session that writes, runs, and persists a small program. Start here if you have not used SCI codemode before.
  • How-to guides. Short procedures for real tasks, such as rebuilding the extension, reviewing a session transcript, or adding a domain operation.
  • Reference. Complete, dry facts: configuration, program format, every binding and domain function, limits, errors, the source tree, and the test suite.
  • Explanation. How a call flows through the system, why the design looks the way it does, the security model, and known limitations.

Conventions

  • Paths without a leading slash are relative to the Guix checkout, /home/engstrand/guix. The extension source lives in desktop/build/pi-sci.
  • Code blocks marked Program are complete codemode inputs. Blocks marked You see show real output captured from this setup.
  • In function signatures, a bare word after the function name is the positional argument. Keys inside braces are options. A key followed by ! is required.
Tutorial

A guided first session. Each step shows a program and the output it produces.

Write your first SCI programs

In this tutorial we write six small programs in a Pi session. Together they read a file, parse JSON, run two tool calls at once, survive a failure, and keep a helper for later calls. Each step shows the program and the output you should see. Run the programs from a Pi session whose working directory is the Guix checkout.

1. Print a value

The input to codemode is raw Clojure source. The value of the last form prints automatically when it is not nil.

Program
(text (+ 20 22))
You see
Script completed
Wall time 0.6 seconds
Output:
42

The first three lines are Pi's result header. Everything after Output: is what the program printed. text prints a string as is and any other value as EDN.

2. Read part of a file

Tool calls return promises. await waits for the result. Here fs/read reads the first four lines and returns them with line metadata.

Program
(let [r (await (fs/read "desktop/build/pi-sci/package.json" {:limit 4}))]
	(text (:text r))
	(text (select-keys r [:start_line :end_line :total_lines :next_line :truncated])))
You see
{
  "name": "pi-sci-codemode",
  "private": true,
  "type": "module",
{:start_line 1, :end_line 4, :total_lines 23, :next_line 5, :truncated true}

:next_line 5 tells you where to continue. Pass it as :start_line in the next call to read on.

3. Parse JSON completely

For JSON, read the whole document as data instead of reading text. fs/read-json returns the parsed document in :value.

Program
(let [r (await (fs/read-json "desktop/build/pi-sci/package.json"))]
	(text (get-in r [:value :scripts :test])))
You see
node --test test/*.test.ts

4. Run two calls at once

Two awaited calls in a row run one after the other. To overlap them, start both and await the group with all. The result is a vector in the same order as the calls.

Program
(let [[log files] (await (all [(jj/log {:revisions "@-" :limit 1})
                               (search/files "*.cljs" {:path "desktop/build/pi-sci/src"})]))]
	(text {:parent (:description (first (:items log)))
	       :cljs (:items files)}))
You see
{:parent "feat(pi-sci): agent ergonomics and fewer bash escapes\n", :cljs ["pi/commands.cljs" "pi/library.cljs" "pi/sci.cljs"]}

Both results are data. jj/log returns commit records in :items. search/files returns paths relative to its search root.

5. Keep going when one call fails

all rejects the whole group if any call fails. all-settled reports each outcome separately, so one missing file does not stop the program.

Program
(let [results (await (all-settled [(fs/read-json "desktop/build/pi-sci/package.json")
                                  (fs/read-json "desktop/build/pi-sci/missing.json")]))]
	(doseq [r results]
		(text (if (= :fulfilled (:status r))
			(str "ok " (get-in r [:value :value :name]))
			(str "failed " (get-in r [:error :message]))))))
You see
ok pi-sci-codemode
failed ENOENT: no such file or directory, open '/home/engstrand/guix/desktop/build/pi-sci/missing.json'

6. Keep a helper for later calls

Every call starts with a fresh interpreter, so an ordinary defn disappears when the call ends. A top-level defsession persists on the current session branch. The helper below contains await, so it needs ^:async.

Program
(defsession ^:async cljs-files [dir]
	(:items (await (search/files "*.cljs" {:path dir}))))
(text (await (session/cljs-files "desktop/build/pi-sci/src")))
You see
["pi/commands.cljs" "pi/library.cljs" "pi/sci.cljs"]

Now use the helper from a new call, list the library, read the helper's source, and remove it. Send this as a separate tool call after the previous one finishes. A call that starts before the definition commits cannot see it.

Program
(text (await (session/cljs-files "desktop/build/pi-sci/src/pi")))
(text (session/definitions))
(text (session/source 'cljs-files))
(text (session/forget 'cljs-files))
You see
["commands.cljs" "library.cljs" "sci.cljs"]
[{:name "session/cljs-files", :kind :function, :parameters "[dir]", :async true}]
(defsession ^:async cljs-files [dir]
	(:items (await (search/files "*.cljs" {:path dir}))))
true

If your branch already has other helpers, they appear in the session/definitions list too.

You have now used the four habits that matter most: await every tool call, group independent calls, reduce results before printing, and persist only helpers you will reuse. The how-to guides build on these for real tasks.

How-to guides

Procedures for specific goals. They assume you have done the tutorial.

Build, install, and reload the extension

Use this procedure after you change anything under desktop/build/pi-sci or after a fresh checkout.

  1. Build the interpreter bundle. From the checkout root, run make pi-sci. Inside codemode, run (await (repo/pi-sci-build)). The first build fetches pinned Clojure dependencies and runs npm ci --ignore-scripts if node_modules is missing.
  2. Link the configuration into your home directory. Run make stow. The target builds the bundle first, then runs desktop/stow-home with Babashka. Afterwards ~/.pi/agent/settings.json and ~/.pi/agent/extensions/sci-codemode/index.ts point into the checkout.
  3. Reload Pi. Type /reload in each running session, or restart Pi.

Check the result with (text (+ 1 2)). The TUI shows the call under the title codemode · SCI.

Know what needs a reload

The extension has two halves that update differently. The difference matters when you test a change in a running session.

You changedTakes effectWhy
src/pi/*.cljs (interpreter, rendering, error hints)On the next call after make pi-scicompileSciSource reads dist/sci.js from disk on every call.
src/*.ts (domains, output budget, prompt, catalog)After /reloadPi imports the TypeScript modules once when it loads the extension.
A domain's operation listAfter both a build and /reloadBindings are generated from the loaded registry and embedded in each call.

If the bundle and the loaded frontend disagree about a domain binding, a call fails with SCI capability bindings are incompatible; run make pi-sci and /reload. A new domain function that the loaded frontend does not know fails with Unable to resolve symbol until you reload.

Keep the Pi settings that enable SCI

These keys in desktop/pi/agent/settings.json select SCI as the only codemode evaluator:

{
	"defaultTools": ["+codemode"],
	"extensions": ["-builtin:codemode"],
	"codemode": { "mode": "only" }
}

-builtin:codemode disables Pi's JavaScript evaluator. "mode": "only" makes codemode the model's only direct tool. Other tools stay callable from inside programs. The bun test tests/pi-codemode.test.ts fails if these defaults change.

Verify a change

Run the full suite

Run make pi-sci-test, or (await (repo/pi-sci-test {:timeout_ms 1700000})) from codemode. The target runs verify.sh, which does the following in order:

  1. Builds the bundle with build.sh.
  2. Installs locked npm dependencies with npm ci --ignore-scripts.
  3. Typechecks with tsc --noEmit.
  4. Lints with Biome through scripts/biome.mjs.
  5. Runs node --test test/*.test.ts against the real Pi SDK with a local fixture provider.
  6. Runs the bun test tests/pi-codemode.test.ts.
  7. Runs the poteto-mode port check, sh -n on the shell scripts, and npm audit --audit-level=high.

A clean run takes about 40 to 90 seconds on this machine. If Biome reports Formatter would have printed the following content, run npm run format in desktop/build/pi-sci and rerun.

Read the result as data instead of printing the whole log:

;; @options: {"timeout_ms": 1800000}
(let [r (await (repo/pi-sci-test {:timeout_ms 1700000}))
      lines (str/split-lines (str (:stdout r) "\n" (:stderr r)))]
	(text (select-keys r [:ok :exit_code :duration_ms]))
	(text (str/join "\n" (filter #(re-find #"✖|ℹ (pass|fail) |error TS" %) lines))))

Two tests measure timing: "all and all-settled realize eager parallel calls" and "deadline escalates past ignored SIGTERM". Under heavy machine load (a load average near 100) they can fail. If one fails, rerun that file alone with node --test --test-name-pattern='...' test/<file>.test.ts before you suspect your change.

Run one program in a clean runtime

To check interpreter behavior without your live session's state, run from desktop/build/pi-sci:

node scripts/run-sci.mjs '(text (+ 20 22))'

The runner loads the extension from source into the real SDK worker with a deterministic local provider. It prints only the codemode result and exits nonzero on failure. It has these restrictions:

  • It permits only read-only fs operations. Every other tool call is blocked.
  • Its working directory is a temporary directory, so use absolute paths.
  • It loads no personal extensions or policy hooks. Use a live session for policy-sensitive checks.
  • It makes no network requests.

Because the runner loads the TypeScript fresh, it is also the way to test frontend changes before you /reload a live session.

Read files and structured data

Read a text file in pages

Use fs/read. Give :start_line with either :end_line or :limit, never both. Continue from :next_line until it is nil.

(defn ^:async read-all [path]
	(loop [start 1 parts []]
		(let [r (await (fs/read path {:start_line start :limit 500}))
		      parts (conj parts (:text r))]
			(if-let [next (:next_line r)]
				(recur next parts)
				(str/join "\n" parts)))))

A single line that is too long for one page returns no text and no advancing :next_line. For machine-readable files, use the structured readers below instead.

Do not use tools/read for data. It returns display text with truncation notices, which json/parse cannot parse safely.

Read a JSON document

(:value (await (fs/read-json "desktop/pi/agent/settings.json")))

The read fails instead of returning a partial value if the input exceeds 1 MiB or is malformed.

Show an image file

(let [r (await (fs/read "/tmp/screenshot.png"))]
	(case (:kind r)
		"image" (image (:image r))
		"image-omitted" (text (:note r))
		(text "not an image")))

Never forward an image-omitted result to image, and never print image data with text.

Review a Pi session transcript

Pi stores each session as JSON Lines under ~/.pi/agent/sessions/<encoded-cwd>/. Records can be several megabytes. Use fs/read-jsonl with field projections and follow every page.

  1. Find the newest sessions. fs/stat returns :modified_ms:
    (let [dir "/home/engstrand/.pi/agent/sessions/--home-engstrand-guix--"
      files (filter #(= "file" (:kind %)) (:items (await (fs/list {:path dir :limit 500}))))
      stats (await (all (mapv #(fs/stat (:path %)) files)))]
	(text (take 5 (map :path (sort-by :modified_ms > stats)))))

    With fs/list you can also pass {:sort "modified"} to get the newest entries first.

  2. Project only the fields you need. :fields maps an output name to a path of property keys. Use string indexes for array elements.
    {:fields {:type ["type"] :role ["message" "role"] :content ["message" "content"]}
 :limit 25
 :max_string_chars 2500}
  3. Loop until :next_cursor is nil, reducing each page as it arrives. This helper folds every record into an accumulator:
    (defsession ^:async scan-jsonl [path opts f init]
	(loop [cursor nil acc init]
		(let [page (await (fs/read-jsonl path (cond-> opts cursor (assoc :cursor cursor))))
		      acc (reduce f acc (:items page))]
			(if-let [c (:next_cursor page)] (recur c acc) acc))))
  4. Print only the reduced result, such as counts or a short list of error messages.

Each item has :line, :value, and :value_truncated. If a projected record would exceed the 48 KiB page limit, the reader halves the string limit for that record until it fits and sets :value_truncated true. Treat clipped values as excerpts.

A session file contains abandoned branches as well as the active one. Counting every record measures the whole file, not the conversation you see.

For a quick quantitative review, run the session metrics script instead.

Know these differences before you choose:

  • search/files honors .gitignore and similar files, also in jj repositories. fs/glob reads no ignore files and includes directories.
  • fs/glob skips dotfiles for * unless the pattern segment itself starts with a dot, like a shell.

  • Every collection result has :truncated. Check it before you claim that a list is complete.

Work with Jujutsu

The checkout uses jj, not git. Reads return records, not CLI text.

(let [[st log] (await (all [(jj/status) (jj/log {:revisions "::@" :limit 5})]))]
	(text {:working-copy (get-in st [:working_copy :change-id])
	       :changed (mapv :path (:items st))
	       :recent (mapv :description (:items log))}))
  • To list changed files, use (jj/files-changed {:revisions "@"}).
  • To read a file at a revision, use (jj/file-show {:path "Makefile" :revision "@-"}) and take :text.
  • To get a patch for review, use (:stdout (await (jj/patch {:from "@-" :to "@"}))). Add :stat true for a summary.
  • To limit any diff or log to paths, pass :paths ["desktop/build/pi-sci"]. Paths are literal prefixes, not fileset expressions.

Mutations always take an explicit message, so jj never opens an editor:

(await (jj/new {:message "feat(pi-sci): describe the change"}))
(await (jj/describe "feat(pi-sci): better message"))
(await (jj/squash {:from "@" :into "@-" :message "combined"}))

For anything without a named operation, jj/run runs jj with an argument vector. It is marked as a mutation. For example, (jj/run {:args ["squash" "--from" "@" "--into" "@-" "--use-destination-message" "--" "VENT.md"]}) moves one file between changes.

If several Pi sessions share one working copy, jj new in one session redirects the other sessions' later edits into the new change. Check (jj/files-changed) before you describe or squash.

Build and check Guix packages

  • To build a package file, run (await (guix/build {:file "package.scm" :load_paths ["modules"]})). A successful, complete build adds :outputs (store paths) and :outputs_complete true.
  • To test the system configuration without activating it, run (await (repo/system-build)), or (await (guix/system-build {:config "desktop/system.scm" :load_paths ["modules"]})).
  • To fetch a source and get its hash, run (await (guix/download "https://example.org/x.tar.gz")). The result adds :store_path and :hash.
  • To lint packages, run (await (guix/lint "python-foo" {:load_paths ["modules"] :checkers ["description"]})).
  • To check formatting without changing files, run (await (guix/style {:files ["modules/engstrand/packages/laya.scm"] :dry_run true})). Without :dry_run, guix style rewrites the files.
  • To run a command in an environment, give an explicit argument vector: (await (guix/shell {:packages ["hello"] :command ["hello"]})).

Long builds need a deadline on both sides. Set the program deadline in the options line and the command deadline in :timeout_ms:

;; @options: {"timeout_ms": 3600000}
(let [r (await (guix/build {:file "package.scm" :load_paths ["modules"] :timeout_ms 3500000}))]
	(text (select-keys r [:ok :exit_code :outputs :truncated :full_output_path])))

Use all-settled when you group a build with optional reads. With all, one missing file rejects the group and cancels the build that is still running.

Keep output within the budget

Each call has an output budget. The default is 10,000 tokens, counted as 4 characters per token. Output that the model does not need costs context and can push useful lines out.

  1. Reduce in SCI before you print. Select keys, count, filter, and take the first few items.
  2. Print one text block per independent piece of evidence. The budget is shared fairly between blocks, so a huge block cannot hide the small ones around it.
  3. If you need more room for one call, raise the budget on the first line:
    ;; @options: {"max_output_tokens": 20000}
  4. If a block is clipped, read the marker. It contains the exact call that reads the full text from the spill file:
    ...[clipped 1615 of 2000 chars; full text: (fs/read "/tmp/pi-sci-output-qmEm7d/output.txt" {:start_line 2 :end_line 2})]...

A command or bash result prints as a status line and raw output, for example [exit 0, 33 ms] followed by stdout. To see the whole result map as data, print (pr-str r).

Check before you print. result/check returns its input, so (result/check r) as the last form prints the whole result. Write (result/check r) first, then print a summary.

Handle failures in a program

Decide up front which failures should stop the program.

  • If every call is required, await all. The first rejection throws.
  • If some calls are optional, await all-settled and branch on :status.
  • To catch one call, wrap it: (try (await (fs/read-json p)) (catch :default e (ex-message e))).
  • Command actions do not throw on a nonzero exit. They return data with :ok false. Call (result/check r) to throw, or test (result/ok? r).
  • Normalized reads, such as jj/log, reject when the command fails or its machine output is incomplete.

A failed program keeps its printed output, and the error appears after it. Tool effects that already happened stay done. The failure report lists them, grouped, for example fs (ok) x4, jj (error). Store writes and defsession declarations from a failed program are discarded.

Do not retry a program that made external changes without checking what already happened. The host never retries for you.

Read the error

Errors point at the problem in your source. A reader error shows both ends of the unclosed form:

Error: Unmatched delimiter: ), expected: ] to match [ at [3 8] at codemode.clj:4:12
  3 |   (let [b (inc a)
             ^ unclosed form opens here
  4 |     (* b 2)))
                 ^ reader stopped here

Common mistakes come with a hint. The errors reference lists them.

Add a domain operation

Add an operation when agents keep reaching for bash to do one thing. Measure first with the session metrics script.

  1. Pick the domain module: src/jj.ts, src/builds.ts (guix, make, repo), src/files.ts (search, fs), or src/sys.ts. For a new domain, create a module that exports a Domain and add it to DOMAINS in src/commands.ts.
  2. Add an entry to the domain's operations map with operation(input, run, positional, mutation, select) from src/operations.ts:
    patch: operation(
	Type.Object({
		revisions: optional(string),
		paths: optional(strings),
		stat: optional(Type.Boolean()),
	}),
	async (a, e) => jj(["diff", ...diffFlags(a, [a.stat ? "--stat" : "--git"])], a, e),
),
    • input is a TypeBox object. It becomes the tool schema, the generated signature, and the accepted-key check.
    • run receives validated arguments and an execution with ctx and signal. Run programs with command(program, argv, a, e), never through a shell.
    • positional names the key that a bare first argument fills. If that key is an array, a single string is wrapped.
    • Set mutation to true when the operation can change state. It is intent metadata for hooks, not a permission check.
    • select returns one field instead of the map, as fs/exists? does.
  3. Return data. Bound collections with collection(items, limit), and fail instead of returning partial machine output.
  4. Add a test to test/ergonomics.test.ts or the domain's test file. Call the function through runtime.call the way an agent does, and assert literal values.
  5. If the domain list changed, update the list asserted in test/semantic.test.ts.
  6. Document the operation in domain-commands.md, then run the full suite and /reload.

You do not edit SCI code. The bindings, the codemode description's signature list, and the key check are all generated from the registry.

Recover a broken session library

Replay fails closed when a helper references a tool that is no longer callable, when the journal is malformed, or when the interpreter fingerprint changed. Every call on that branch then fails before your program runs.

  1. Run /sci-library to see the revision and the active definitions.
  2. If the cause is a missing tool, restore the tool and stop here.
  3. Otherwise run /sci-library reset. It records an empty library on the current branch without evaluating old source. Stored task data is unchanged.

To undo a reset, branch from the entry before it. The earlier journal is still on that branch.

To remove one helper on a healthy branch, call (session/forget 'name). Forgetting does not free journal capacity. The journal holds at most 512 operations and 131,072 source characters.

Measure agent friction

Run the metrics script from desktop/build/pi-sci:

node scripts/session-metrics.mjs        # the 7 newest sessions
node scripts/session-metrics.mjs 20     # the 20 newest sessions
node scripts/session-metrics.mjs a.jsonl b.jsonl

For each session it counts codemode calls and errors, calls that use tools/bash, tools/read, or catalog lookups, and results that show escaped bash maps, whole-output truncation, clipped blocks, parse errors, validation errors, and hints. It ends with the bash share of all codemode calls.

The baseline before the ergonomics change (seven sessions, 2026-10-07 to 2026-10-08) was 376 codemode calls, 42.0% bash share, 144 escaped bash maps, 35 truncated outputs, and 7 parse errors. Compare against it after a guidance or capability change, and give the new numbers a few sessions before you draw conclusions.

Use bash deliberately

Bash is right when no semantic function exists and the work needs a host program or real shell behavior, such as pipes into a project tool, emacsclient, or npm run format.

(text (await (tools/bash {:command "cd desktop/build/pi-sci && npm run --silent format" :timeout 120})))

The result is a map with :output, :exit_code, :truncated, and sometimes :full_output_path. text prints it as [exit 0, 0.2 s] and the output.

Keep the analysis in SCI. Do not write temporary Python, JavaScript, or shell programs to filter or count output that SCI can process.

Changes to the system prompt

On before_agent_start the extension does two things to the prompt:

  • It rewrites two rules that Pi generates. "Use bash for file operations like ls, rg, find" becomes a rule that names fs/read, fs/list, fs/glob, search/files, and search/text. "Use read to examine files instead of cat or sed." becomes the same rule with fs/read. The table is PROMPT_REWRITES in src/catalog.ts.
  • It appends a library summary: the first 12 hex digits of the branch revision, the count of active definitions, and up to 8 of them.

The codemode tool also contributes three prompt guidelines (registered in src/extension.ts): prefer semantic namespaces over bash, collect effects then reduce, and persist reusable helpers with defsession.

Program format

The code parameter is raw Clojure source. It is not JSON and not a fenced code block. Constrained sampling uses a grammar that accepts an optional options line followed by any source.

Options line

The first line may set options as JSON:

;; @options: {"max_output_tokens": 20000, "timeout_ms": 600000}
FieldDefaultMeaning
max_output_tokens10000Output budget in tokens of 4 characters. Applied per block by the extension.
timeout_msnoneDeadline for the whole program, including library replay. Without it the program has no deadline.

Any other field is an error. The options line must be followed by source. Reported line numbers match your original source, with the options line counted as line 1.

Evaluation

  • The body is async. Top-level forms run in order. Each form finishes, including its awaited calls, before the next starts.
  • require forms must come before any executable form and may only name supplied namespaces.
  • A top-level defsession takes effect at its position in the program.
  • When the last form returns a non-nil value, it is printed as if passed to text.
  • Calls still running when the program ends are cancelled.
  • The QuickJS VM has a 256 MiB memory limit. Exceeding it throws out of memory inside the program.

Budget

budgetOutput in src/output.ts runs on every result after Pi's executor returns.

  • The budget in characters is max_output_tokens × 4, minus the size of protected blocks.
  • Protected blocks are never clipped: blocks that start with Script error:, SCI transaction failed:, [Image , or Note: models.generateImages.
  • The remaining budget is shared by water-filling. Blocks smaller than an equal share keep their full text. The rest get the same cap, never less than 200 characters.
  • A clipped block keeps 60% of its cap from the start and 40% from the end, around a marker with the exact fs/read call for its lines in the spill file.
  • The spill file is /tmp/pi-sci-output-XXXXXX/output.txt, mode 0600. It holds all text blocks joined by newlines. Its path is also in the result's details.fullOutputPath.
  • Pi's own whole-output truncation is set to 2,500,000 tokens (EXECUTOR_OUTPUT_TOKENS), so it acts only as a memory backstop.

Session library journal

Persistent definitions are stored as an ordered journal of operations in the session file. Each successful program that declares or forgets appends one codemode-store entry:

{
	"type": "custom",
	"customType": "codemode-store",
	"data": {
		"set": { "key": "value" },
		"delete": [],
		"sciEnvironment": {
			"version": 1,
			"runtime": "sci-5fe89056384418be50d232b4278344cb3a1a526b-library-v1",
			"reset": false,
			"operations": [
				{ "op": "define", "name": "cljs-files", "source": "(defsession ^:async cljs-files [dir] ...)",
				  "kind": "function", "parameters": "[dir]", "async": true },
				{ "op": "forget", "name": "cljs-files" }
			]
		}
	}
}
  • set and delete are Pi's ordinary store changes. Pi's own store reader ignores sciEnvironment.
  • Inside the VM the delta travels under the reserved store key __pi_sci/environment-delta. The host removes the key before it writes the entry.
  • kind is function or value. A value has parameters null and async false.
  • The journal for a branch starts at the newest entry with reset: true and includes every later entry on that branch.
  • The revision is a SHA-256 over the runtime string and each entry's ID and delta. The host compares it before commit.
  • A different runtime string makes the journal incompatible. Change the string when declaration or replay semantics change.

These names are reserved and cannot be declared: definitions, source, forget, text, println, prn, image, exit, store, load, unstore, all, all-settled. Valid names match [A-Za-z_][A-Za-z0-9_!?*+<>=$%.-]*.

A persisted function may not contain def, defn, defmacro, defsession, declare, ns, in-ns, require, alias, refer, refer-clojure, with-redefs, or with-redefs-fn, and may reference only supplied namespaces. A persisted value must be a literal JSON-compatible value.

Build pipeline and test suite

build.sh

  1. Creates dist/ and runs npm ci --ignore-scripts if the Pi SDK is missing from node_modules.
  2. node scripts/prepare-search.mjs checks the SHA-256 of Pi 1.0.4's grep.js, find.js, and read.js, patches exact anchors to return structured records, and writes dist/pi-*.mjs. A changed upstream file fails the build.

  5. mv dist/sci.pending.js dist/sci.js publishes the bundle atomically, so a running session never reads a half-written file.

Explanation

How the system works and why it is designed this way.

The life of one codemode call

This section follows one call from the model's output to the session file. Knowing the order explains most of the behavior you see, including what survives a failure and why some changes need /reload.

  1. The model writes source. Pi's provider adapter constrains the code argument with a small grammar: an optional ;; @options: line and then any text. The model sees the tool as "Run Clojure that calls other tools", with SCI_INTRO, the domain signatures, and as many tool declarations as fit in codemode.inlineBudget.
  2. The extension takes a snapshot of the branch. execute in src/extension.ts records the session ID, the current leaf, the newest codemode-store entry, and the library journal with its revision hash.
  3. It builds a private executor. It calls Pi's createCodemodeExtension again with an appendEntry that captures the store write instead of writing it. This keeps Pi's stock executor, worker, limits, and model accounting, while the extension decides whether to commit.
  4. It compiles the call. compileSciSource reads dist/sci.js from disk and wraps it in JavaScript that passes the callable tools, a catalog shim, the domain bindings, the journal, and guarded store functions to piSciRun. The source travels as a JSON string. It is never evaluated as JavaScript.
  5. The executor starts a fresh QuickJS worker. The worker has a 256 MiB heap and the program's deadline, if one is set.
  6. SCI replays the library. piSciRun creates a new SCI context with the denied symbols removed and the namespaces installed. It replays every journal operation with effects disabled. Any tool call, output, or store access during replay throws.
  7. SCI runs the program. It reads forms one at a time, checks require placement, and validates defsession forms before running anything. Each form runs inside an async function. The next form starts only when the previous one's promise settles.
  8. Tool calls leave the sandbox. A call such as (jj/log {:limit 5}) checks its keys in SCI, converts the map to JSON, and calls the jj tool with operation: "log". Pi runs it through its normal pipeline: tool_call hooks, schema validation, the handler, and tool_result hooks. The structured result comes back as keyword maps.
  9. The executor formats the result. It adds the header, the printed blocks, the last value, and on failure the error with a list of tool calls already made.
  10. The extension applies the output budget. budgetOutput cleans the failure report, shares the budget across blocks, and writes a spill file when it clips.
  11. The extension decides whether to commit. On success it checks that the session, the branch anchor, the newest store entry, and the library revision are all unchanged. Then it appends one codemode-store entry with the task data and the library delta. On any mismatch it marks the result as failed and commits nothing.
  12. The TUI renders the call. It shows the title codemode · SCI and the first eight lines of highlighted source, with the rest available when expanded.

Two consequences follow. First, steps 2, 3, 10, and 11 are TypeScript loaded once, while steps 6 and 7 come from a file read on every call. That is why interpreter changes apply immediately and frontend changes need /reload. Second, tool effects in step 8 happen immediately, but data and definitions are only written in step 11. A failed program therefore leaves real side effects and no stored state.

About running SCI inside Pi's sandbox

The setup could have kept Pi's JavaScript evaluator, forked Pi, or run a separate Clojure process. It does none of these. It compiles SCI with ClojureScript and runs it inside the QuickJS worker Pi already uses.

The reason is that the sandbox is the part worth keeping. Pi's executor already enforces memory and time limits, cancels pending calls, routes every tool call through hooks, accounts for model usage, and saves images. A replacement tool registration that reuses the stock executor inherits all of that. A fork would have to maintain it. A separate process would have to rebuild it.

Clojure earns its place for this workload. Agent programs are mostly data transformation: select keys, group, count, filter, join. Clojure's persistent data structures and sequence functions do that in a few forms, and EDN output is compact and readable. SCI adds a controlled environment where the allowed namespaces and denied symbols are explicit.

The cost is a build step with a JVM, about 40 seconds, and a pinned SCI commit that needs a build-time patch. The patch fixes SCI's async body transformation, which let later expressions start before earlier awaited calls finished. Pinning makes that patch safe: prepare.clj fails the build if the patched source no longer matches exactly.

JavaScript is not a fallback. The tool accepts only Clojure, the obsolete codemode.language setting is ignored, and a missing bundle is an error. A silent switch to another language would make the model's programs mean something different without anyone noticing.

About explicit await

Every tool call returns a promise because the result arrives from outside the worker. SCI supports await by rewriting functions marked ^:async into promise chains. The setup exposes this directly instead of hiding it behind blocking-looking calls.

Explicit waits make two things visible in the program text: which calls depend on each other, and which run at the same time. (await (all [...])) is the only way to overlap calls, so concurrency is always deliberate. Pure computation stays synchronous and needs no annotation.

A different interpreter could make tool calls look blocking. That would need its own scheduler inside QuickJS and would break the executor's cancellation model, where unawaited calls are cancelled when the program ends. The current design keeps Pi's contract and asks the model for one extra word per call.

About typed domains instead of a shell

Bash lets an agent do anything, and that is the problem. Output arrives as text that the agent must parse, a pipeline hides which programs ran, and policy hooks see one opaque command string.

Each domain is one registered Pi tool whose schema is a union of operations. A call carries an operation name and typed arguments, so hooks see {operation: "squash", from: "@", ...} rather than a string to re-parse. Handlers build argument vectors for spawn without a shell, so a path with spaces or $(...) is just a string. Results are data, and reads that cannot parse complete machine output fail rather than guessing.

One tool per domain, not per function, keeps the tool list short and the descriptions in one place. The alternative of a hidden host executor called by trusted SCI wrappers was rejected. It would skip Pi's tool pipeline, and with it every guard.

The registry is the single source of truth. From each operation record the extension derives the JSON schema, the SCI binding, the positional argument, the accepted-key check, the signature line in the codemode description, and the mutation marker that hooks can read. Adding an operation never touches the interpreter.

Some exclusions are deliberate. There is no git namespace because this checkout uses jj, and a git function would invite mixing the two. There is no rg namespace because search goes through Pi's own grep. There is no generic process/run, because it would turn every domain back into a shell.

Bash stays as the escape hatch, and the session review showed why it needed steering. Before the ergonomics change, 42% of codemode calls used bash, mostly for ls, find, du, df, and printenv. The guidance even told agents to use bash for file discovery. The fix was to remove that guidance first, then add fs/glob, fs/disk-usage, sorted listings, and the sys domain for the commands that remained.

About replaying helpers instead of keeping workers

Each call gets a fresh worker and a fresh SCI context. Persistent helpers are rebuilt every time by replaying a journal of their source. Keeping a worker alive between calls would be faster, so why replay?

Pi sessions branch. You can rewind, fork, compact, and reopen a session file days later. A live interpreter has one history. A journal stored in the session entries has the same shape as the conversation, so each branch sees exactly the helpers declared on its own ancestry, and reopening the file restores them. No interpreter object, permission, or tool reference outlives the call that created it.

Replay also keeps capabilities current. A helper compiles against the tools callable now. If a tool was removed, replay fails instead of resurrecting old access.

The restrictions on defsession follow from replay. A value must be a literal because a computed initializer would run again, with effects, on every call. A function may not define vars or change namespaces because replay must produce the same environment each time. A function may not capture a temporary def or a local binding because those do not exist during replay.

Commits are transactional. A program's definitions and store writes go into one entry, written only after the host confirms nothing else committed in the meantime. A conflict discards both. The host never reruns the program, because its tool effects already happened.

Replay cost grows with the journal, which is capped at 512 operations and 128 KiB of source. Nobody has measured it as a problem yet. The design record keeps a fork with persistent workers as an option if a measurement ever shows one.

About structured reads and the output budget

Two kinds of truncation used to cost agents the most time: reads that cut data, and output that cut evidence.

tools/read is built for showing files to a model. It stops at 2000 lines or 50 KiB and adds notices to the text. That is fine for reading code and wrong for data. A session transcript has single lines larger than a page, and a parser fed display text fails or, worse, succeeds on a fragment. fs/read-json and fs/read-jsonl therefore parse complete records and fail rather than return a partial value. JSONL pages carry a byte cursor with the line number, so a reader can resume exactly and prove it saw every record.

Output had the opposite problem. Pi's executor joins every printed block and, when the total is too long, keeps the start and the end. A program that printed five file excerpts and one long log lost the excerpts in the middle. Agents learned to make smaller calls and reread, and the same complaint appears five times in VENT.md.

Instructions to "print less" did not stop it, so the extension now enforces a fair share per block. Small blocks always survive. Large blocks keep both ends and say exactly how to read the rest. Errors are never clipped, because an error you cannot read is the most expensive output of all.

Rendering command results as a status line plus raw text fixes a related waste. Printed as EDN, a bash result shows its output as one escaped string with \n sequences, which is hard to read and costs extra tokens. 144 results in the reviewed sessions looked like that.

About the security model

The boundary is layered. No single layer is the whole story, and the tests are evidence, not a formal proof.

  • QuickJS. The outer isolation. The program runs in a WebAssembly VM with a memory limit and no access to Node APIs.
  • SCI. The program cannot reach JavaScript globals, interop, eval, namespace loaders, files, processes, timers, or the network. Only supplied namespaces can be required.
  • Pi's tool pipeline. Every effect is a registered tool call. Extensions see it in tool_call and tool_result hooks and can block or redact it. Domain calls expose their operation to hooks.
  • Operating system. Tools still run with your user's permissions. bash, make, guix, and jj can do whatever you can.

Several things are intentionally not security boundaries. Mutation markers describe intent for hooks and humans. They grant nothing. Read-only operations can still run code: make/dry-run evaluates Makefile shell expressions, and jj reads can snapshot the working copy. sys/env redaction is a guard against accidental disclosure by name, not a secret store. A variable named DATABASE_URL with a password inside is not redacted.

Data that leaves the sandbox follows Pi's rules. Store values persist in the session file. Spill files, and command logs kept for truncated output, are written under /tmp with mode 0600. Nothing deletes them automatically.

Known limitations

  • Mixed versions in a live session. After a build without /reload, the interpreter is new and the TypeScript frontend is old. New domain functions do not resolve, and the output budget, prompt rewrite, and key checks keep their old behavior.
  • Shared working copies. Pi sessions that share one jj working copy write into whichever change is @. Check changed files before you describe or squash.
  • Prompt rewrites depend on Pi's wording. If Pi changes the text of a rule, the rewrite stops matching. test/ergonomics.test.ts catches that for Pi's own prompt. Providers that build their own system prompt may not see the rewrite at all.
  • Dependent calls must be sequential. A call that starts before another call's defsession or store commits cannot see it, and concurrent commits conflict.
  • Cursors are not snapshots. A JSONL cursor is valid only for the same file, unchanged or appended.
  • Search edge cases. Filenames containing newlines may not round-trip through search/files. Binary and non-UTF-8 paths follow Pi's existing behavior.
  • Oversized single lines. fs/read cannot page through one line larger than its page.
  • fs/glob is not search. It reads no ignore files and stops at 10,000 directories. Use search/files for project trees.
  • Timing-sensitive tests. Two tests can fail when the machine is saturated. Rerun them alone before you investigate.
  • Process and memory facts are Linux-specific. sys/memory and sys/processes read /proc.
  • Windows. Command cancellation kills only the immediate process. This setup runs on Linux.
