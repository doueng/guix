# Guix on the internal drive

Personal Guix System configuration for an M1 MacBook Air. Guix boots from the internal Btrfs root and EFI system partition. macOS remains an independent recovery environment.

`desktop/system.scm` and `desktop/home.scm` are entry points; `modules/engstrand/config.scm` composes features in `modules/engstrand/features/`. Guix packages and services live under `modules/engstrand/`.

Mutable application configs live under `desktop/configs/<app>` and are linked directly into the corresponding `~/.config/<app>` directory using GNU Stow. `ideavim` is the exception. It mirrors the home layout and is stowed into `~`, because the IntelliJ Flatpak only reads `~/.ideavimrc`. `make home-apply` reconfigures Guix Home and refreshes these links; `make stow` refreshes only the mutable links. Run `make pull` after changing `channels.scm` to update your user Guix profile. Daily targets use that pulled Guix: `make check` runs `desktop/system-facts.scm` and builds the system, which includes Home, without activation; `make switch` runs the same facts script first, so it needs no separate check. The facts script prints the folded daemon, sysctl, Shepherd and mount configuration and rejects mount(8) flag words in file-system options; `make home-build` builds Home without activating it; `make switch` applies the Guix system. Use `make repro-build` to build the system directly from the pinned channels with `guix time-machine`.

Guix Home manages packages, services, environment variables and store-backed files. Build-time package assets are kept separately from `desktop/configs/`. The desktop shell is dusk, built in-tree under `desktop/build/dusk/` (GPUI layer surfaces described by a Babashka config in `desktop/configs/dusk/config.clj`, hot-reloaded on save). Run `make dusk` to build it after cloning or changing its Rust code, `make dusk-test` for isolated runtime and headless GPUI regression tests, and `make dusk-verify` to check wallpaper, notifications, OSD, launcher and reload on the running session. `desktop/bin/`, `desktop/icons/`, and `desktop/pi/agent/` are Stowed into `~/.local/bin/`, `~/.local/share/icons/`, and `~/.pi/agent/`. Stow refuses to replace existing unmanaged files or links; inspect and remove verified obsolete links when migrating.

Some Home packages are nixpkgs binaries from cache.nixos.org rather than Guix builds. `modules/engstrand/nixpkgs/packages.sexp` lists the nixpkgs attributes, `make nixpkgs-lock` resolves them into `lock.sexp` next to it, and `(nixpkgs-package "attr")` from `(engstrand nixpkgs)` installs one. `make nixpkgs-import` copies the locked closures into `/gnu/store` with `/nix/store` rewritten to `/gnu/store`; the build, switch and Home targets run it first, and `make nixpkgs-verify` checks the store items against cache.nixos.org. The import is signed by the key from `make nixpkgs-key`, which the daemon trusts through `signing-key.pub` in the same directory. See [the design](docs/nixpkgs-bridge/design.html).

Pi uses SCI codemode inside its existing QuickJS sandbox. `make pi-sci` builds the pinned interpreter, `make pi-sci-test` verifies the installed Pi and SDK runtimes, and `make stow` builds SCI before linking configs. See [SCI codemode](desktop/build/pi-sci/README.md) for SCI-only configuration, bindings, limits, and tests.
